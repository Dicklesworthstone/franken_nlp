## 1. Mission & non-negotiable goals

**Mission.** `franken_nlp` is a pure-Rust (Rust 2024, one exactly pinned dated nightly — §3.4), memory-safe, CPU-hyper-optimized **library + one CLI program (`fnlp`, also shipped under the long name `franken_nlp`)** that runs the **Nanbeige4.2-3B** language model **with no general ML framework** — and turns it into a complete local NLP toolbox: structured extraction, NER + entity resolution, sentiment/dimension scoring, zero-shot classification, PII redaction, faithfulness judging, summarization, keyphrases, QA, and plain generation. `unsafe_code = "deny"` applies at crate roots; only enumerated SIMD/mmap modules may opt into scoped audited islands (§1.1 G4).

We achieve this by transforming the model's bf16 weights into a custom quantized on-disk form (int8 first, int4 in refinement rounds), distributing the transformed artifacts as GitHub release assets (fixed 1,957,046,720-byte parts except the tail, each under GitHub's 2 GiB limit; hash-verified and reassembled by `fnlp pull`; Apache-2.0 license text + attribution carried per §5.7), and writing **model-specific kernels** whose only job is to run *this one model* as fast as possible on:

- **Apple Silicon / ARM64** — M4/M5 family: NEON, FEAT_DotProd (SDOT), FEAT_MATMUL_INT8 (SMMLA / i8mm), high-bandwidth unified memory, big SLC
- **AMD / Intel x86-64** — high-core-count parts first: Threadripper/EPYC Zen 3 (AVX2 ceiling — the reference `trj` machine is a 5995WX-class part), Zen 4/5 and Xeon (AVX-512-VNNI / AVX-VNNI), with AVX2 as a first-class, proof-carrying tier, not a fallback afterthought

CUDA is outside the v1–v2 plan entirely; any future CUDA path requires a new architecture decision and plan revision rather than being treated as latent scope. The **Apple-silicon integrated GPU is explicitly in scope** (owner ruling, 2026-07-31): a Metal path via the `ft-kernel-metal` crate is a planned M4/M5 acceleration track — prefill first, where the compute-bound work lives, over the same unified memory the CPU kernels already share — developed once the CPU core is parity-proven (§11 Phase 7), gated by the same L-ladder with GPU numerics as their own named §1.1.1 profile. **CPU remains the reference implementation, the correctness authority, and the portable product floor** because most machines that need local NLP (laptops, CI runners, agent hosts, edge boxes, privacy-constrained servers) have no usable CUDA GPU — and because this model is small enough (≈ 4.17 B params, ≈ 3.1–4.7 GB for the default int4/int8 recipes; smaller recipes require separately-gated embedding/lm-head quantization) that a well-written CPU path is genuinely fast.

The engine is built on **frankentorch** (custom tensors / serial-range CPU kernel leaves — consumed below autograd, never as an ambient scheduler) and **asupersync** (the structured execution foundation for orchestration, admission, budgets/cancellation, IO, and scoped CPU-team lifecycle). Optional metadata/run/job state uses **frankensqlite** (`fsqlite` — never `rusqlite`); document text and model output are never persisted by default. Direct dependencies outside the FrankenSuite are frozen to the three owner-approved families in §3.4. It is **agent-ergonomic** (robot / JSON / NDJSON mode, stable versioned schema, explicit exit codes) and **embeddable** as a plain Rust library with a blocking, sync public API.

### 1.1.1 Numerics and determinism profiles (the vocabulary every fidelity claim uses)

The pinned HF implementation is a **bf16 program with explicit cast points**: RMSNorm reduces in f32 and casts back to the input dtype, attention softmax runs in f32 and casts back to the query dtype, RoPE frequencies/cos/sin are built in f32 and cast, and final logits are exported as f32 **[OBSERVED@pin; OQ-30 archives the complete cast map]**. A pure-f32 engine is therefore a *different numerical program* from the reference, and no single “exact match” sentence can govern both. Every conformance result, cache key, receipt, benchmark row, and task envelope names exactly one profile:

1. **`hf-bf16-eager`** — the behavioral reference: bf16 values with the pinned cast points, eager/manual attention, f32 norm/softmax internals, f32 exported logits. This profile owns “matches HF” claims.
2. **`diagnostic-f32`** — bf16 source values widened once, then f32 activations throughout. This is the structural/bisect oracle (it localizes divergence to an operator) and is **not** presumed token-identical to `hf-bf16-eager`; where a token flips, the divergence is a named fixture, not a build failure.
3. **`strict-quantized-vN`** — a versioned quantization algebra: exact integer reductions, fixed scale-application and reduction order, and batch-1 ≡ batch-M plus cold ≡ forked-prefix equality on one compatibility key (§4.3.1). Its relationship to bf16 is expressed through preregistered logit/argmax/token/task budgets, never inherited exactness.
4. **`fast-vN`** — explicitly opt-in approximations (vectorized transcendentals, relaxed reduction order). Same-host reproducibility plus measured quality bounds replace any portable bit-identity claim; fast profiles may not reuse strict-profile cache entries.

“Deterministic” never silently means cross-ISA floating-point bit identity: integer dot products may be cross-ISA exact, while norms, rsqrt, softmax, dequantization, and sampling carry separately named contracts (§9.2). All `FNLP_*` environment variables are CLI inputs snapshotted once into `NlpEngineBuilder`; library code never reads them ambiently (§8.5). Profile definitions are frozen by OQ-30 evidence in Phase −1 and versioned thereafter.

### 1.2 Explicit non-goals (v1)

- **Not** a general inference runtime, not a model zoo, not a router. **One model** (Nanbeige4.2-3B), end-to-end. (franken_ocr grew a small certified zoo *after* its core was proven; if that ever happens here it is a post-v2 decision, and nothing in v1 may pay a generality tax for it.)
- **Not** a per-token classical-NLP pipeline. **POS tagging, dependency parsing, and lemmatization are explicit non-goals**: a finite-state/statistical tagger (spaCy-class) does those at ~10⁴–10⁵ tokens/s/core; a 3B autoregressive LLM cannot compete on cost and we will not pretend otherwise. What we replace is the *other* 90% of why people reached for spaCy + cloud APIs: NER, entity resolution, classification, extraction, redaction, scoring.
- **Not** an embedding engine. Dense retrieval embeddings are **frankensearch**'s job; `fnlp` interoperates (shared NDJSON conventions) rather than duplicating it.
- **Not** training or fine-tuning. Inference only. No autograd, no optimizers, no backward kernels — we reach past ft-api's session/tape layer straight to `ft-kernel-cpu`'s free-standing kernel functions.
- **Not** an HTTP server in v1. The persistent-process story is the **NDJSON batch daemon** (stdin/stdout, §8.4); an OpenAI-compatible `fnlp serve` is a Phase 7 stretch decision.
- **No GPU dependency in v1, and no CUDA ever.** The Apple integrated GPU (Metal via `ft-kernel-metal`) is an affirmed M4/M5 acceleration track, but it lands after the CPU core is parity-proven and never becomes a requirement: every task runs at full fidelity on CPU alone, and the CPU path stays the correctness authority.

### 1.3 Why this model (the one-paragraph pitch)

Nanbeige4.2-3B is reported by its authors as an unusually strong sub-4B open-weights model for reasoning + agentic work **[REPORTED]** (SWE-Bench Verified 63.6, GPQA-Diamond 87.4, HMMT-Feb-2026 82.8, Terminal-Bench 2.0 44.1 — with the card reporting wins over larger comparison models). The model card declares Apache-2.0, a 256K context, and a controllable thinking mode. Redistribution authority is settled by that Apache-2.0 declaration (§2.2); release work mechanically carries and verifies the license/attribution/modification bundle, while the quality and practical-context claims remain reported until independently reproduced. Its **Looped Transformer** design (22 physical layers executed twice → 44 effective layers) is precisely the shape that rewards a bespoke CPU engine: the weight footprint of a 3B non-embedding decoder with the compute schedule of a roughly 6B one, so the algorithm performs **two logical reads of every physical decoder weight per generated token** (measured DRAM/SLC traffic is reported separately, since loop 2 may reuse cache-resident lines — §10.1) — which doubles the payoff of aggressive quantization, weight-layout specialization, and batch amortization (§3.1, §6). A general framework treats the loop as two generic passes; we treat it as *the* defining property of the machine we are building.

### 2.1 One-paragraph orientation

Nanbeige4.2-3B is a **dense, decoder-only, Llama-family transformer with one structural novelty active in this checkpoint: the loop**. The released checkpoint is a 22-layer GQA transformer (hidden 3072, 48 query heads / 8 KV heads, head_dim 128, SwiGLU intermediate 10752, RMSNorm, RoPE θ=7×10⁷, max positions 262144, vocab 166144, untied embeddings) whose layer stack executes **num_loops = 2** times per forward — 44 effective layer executions from 22 layers' weights **[OBSERVED@pin]**. `_get_loop_cache_layer_idx` maps `(loop, layer)` to `layer + loop × 22`, yielding 44 independent KV slots **[OBSERVED@pin]**. The modeling file also implements mHC hyper-connections, depth attention, LoopSplit, and hashed n-gram embeddings, but the 201-name checkpoint index contains none of their tensors and the released config enables none of them **[OBSERVED@pin]**. It is an instruction-tuned, tool-calling, thinking-mode model intended as a local personal assistant, trained with SFT + RL **[REPORTED]**.

### 2.4 The loop — the one structural novelty active in this checkpoint

What the pinned config, checkpoint index, and loop driver say **[OBSERVED@pin; Phase −1 must promote to EVIDENCED]**:

- `num_loops = 2`; `_get_num_loops()` returns it because `loop_loss_weights=[]` and double LoopSplit is disabled: exactly two sequential passes over layers 0…21.
- `_get_loop_cache_layer_idx(layer, loop)` is `layer + loop * num_hidden_layers`; positions/cache-position are reused, but each pass writes its own 22-slot KV region: **44 independent KV entries per token position**.
- `skip_loop_final_norm=false`; after each 22-layer pass the loop driver executes the same final RMSNorm. Loop 2 consumes loop 1's normalized output directly. There is no embedding re-injection or loop-boundary projection.
- Depth attention, mHC/hyper-connections, LoopSplit, and n-gram embeddings are inactive, and their tensor-name families are absent from the 201-entry index. The card describes family-level innovations; this checkpoint's active parameterized surface is the minimal looped decoder.
- The loop's positions, cache positions, masks, and RoPE positions are the same logical positions in both passes. The L2 conformance ladder still names the boundary separately because an implementation can reproduce plausible text while applying this rule in the wrong place.

**Kernel implications (why the loop changes everything):**

1. **Per-token decode streams the full 3,149,008,896-parameter physical layer stack TWICE** (plus the reused 3,072-parameter final norm after each pass). Consequences: quantization saves bytes on both passes; batching shares each pass's stream across M sequences (one stream per physical layer **per loop**, two total, rather than 2M); rooflines include the ×2.
2. **KV cache is 44-deep, not 22-deep.** Per position: 44 × 2 (K,V) × 8 heads × 128 dim × 2 B = **180,224 bytes = 176 KiB/token** bf16. One sequence costs 704 MiB at 4K, 5.5 GiB at 32K, and 44 GiB at 256K before allocator/page metadata; int8 halves payload. This makes lazy paging/admission (§6.8–§6.9), not the advertised context number, authoritative.
3. **Prefill compute is also ×2** (≈ 12.6 GFLOP/token; §10.1) — prefill is compute-bound, so the tiled int8 GEMM quality (SMMLA/VNNI/AVX2) directly sets scoring throughput, where prefill dominates (§7 tasks are mostly prefill-heavy).
4. **The loop suggests—but does not automatically provide—a draft/verify seam.** Loop-1 hidden state can be projected through `lm_head` to propose tokens, but a correct speculative algorithm must verify a *sequence* with the full two-loop model and preserve the target distribution/token stream; merely accepting a loop-1 token on a confidence threshold is approximate decoding, not speculation. No loop-1 loss is configured, so draft quality may be poor. This remains a default-off research card (§10.5), gated on an exact rejection sampler/verification construction and allowed to die in the negative-evidence ledger.

## 3. Why pure-Rust + frankentorch + asupersync

### 3.1 The generality-tax wedge — *one fixed model, compile-time-known shapes, no framework*

A general ML framework pays a generality tax on dynamic op/dtype/graph handling. `franken_nlp` runs one model whose **weight-side and head dimensions** are fixed—hidden 3072, q 6144, KV 1024, head_dim 128, intermediate 10752, 22×2 passes, vocab 166144. Batch rows, sequence length, candidate count, and resource budgets remain dynamic and keep explicit tail paths. Fixed inner shapes let us:

- **Specialize kernels to fixed weight-side shapes** — `const`-generic tile sizes; 3072/6144/1024/10752/128 all tile cleanly for selected SMMLA/VNNI/AVX2 K/N geometries, so those fixed axes need no runtime shape branching. Dynamic M/T/candidate/page tails remain explicit and proved; converter zero-padding is permitted only where the selected tile contract records it.
- **Pre-pack weights offline** into arch-specific interleaved int8/int4 tiles — the converter knows the exact layout each kernel wants; the runtime never reshuffles (the llama.cpp "aarch64 repack" lesson, done at convert time instead of load time).
- **Pre-size and reuse the admitted hot working set** — activation rails, bounded candidate/logit scratch, and mask words come from engine-owned arenas; KV uses lazy pages from a budgeted pool rather than allocating the impossible configured-context maximum up front. Page acquisition happens only at admission/page boundaries; the inner token/layer loops make zero general allocator calls.
- **Schedule the loop explicitly** — per-loop KV binding, boundary norm, buffer reuse, and batch layer-major execution. Each physical layer still streams once in loop 0 and once in loop 1, but each stream serves all compatible rows instead of one sequence.
- **Skip autograd entirely** — inference only; straight to `ft-kernel-cpu`'s free-standing kernels over `&[f32]`/`&[i8]` slices.
- **Fuse only adjacent dataflow that survives an equivalence proof** — input quantization shared across gate/up, projection epilogue→RoPE, residual→next RMSNorm, GEMV→argmax — because no framework boundary forbids it, but algebra and dependencies still do (§6.11).

This is the same wedge franken_ocr proved (and franken_whisper and the frankensearch int8 reranker before it), with one addition: **the loop doubles the value of every weight-side byte saved and every weight-stream amortized**, because the stream happens twice per token (§2.4).

### 3.2 Why frankentorch (consumed at the kernel level) — and the measured lessons that bind us

At inspected commit `523aaf…`, frankentorch provides a valuable **baseline**, not this engine's finished kernel layer: `quantize_per_output_channel_i8` (symmetric rows, current output range `[-127,127]`), `linear_int8_dynamic_f32` (per-row dynamic s8 activation quantization, i32 accumulation, SDOT / AVX-512-VNNI / scalar dispatch), a prepacked SDOT entrypoint, `rms_norm_forward_f32`, `sdpa_forward_f32`, softmax/SiLU/matmul/argmax primitives, and safetensors loading through `ft-serialize` **[OBSERVED@pin]**. The dynamic linear allocates and repacks work that a fixed-model hot path cannot afford; it has no AVX2 or SMMLA tier; the inspected SDPA is dense per-head rather than a model-native 48:8 GQA implementation; and `ft-kernel-cpu` currently makes Rayon an unconditional dependency and parallelizes many public entrypoints through its global pool. We reuse only proved serial/tile leaf surfaces as f32/L1 or scalar/SDOT baselines, then build the missing fixed-shape/prepacked/GQA paths under asupersync-owned CPU-team scheduling. Phase 0 must first make the relevant frankentorch leaf surface available without Rayon in the release graph. §3.5 records every reuse claim so “built on frankentorch” never becomes “assumed frankentorch already has it.”

**The measured lessons from the frankensearch/franken_ocr kernel campaigns are inherited as doctrine, not re-litigated:**

1. **The gap to MLAS/ONNX-class baselines is kernels-below-peak, NOT framework overhead.** A naive "fused tape-free forward" that swapped SIMD kernels for scalar ones regressed 3–10×. Every op must stay at peak; fusion is worthless otherwise.
2. **Un-blocked SMMLA is a trap** — its extra MAC density can be lost to load-bound stalls; the candidate needs register/cache blocking + offline pre-packing. The exact compute:load ratio and tile are measured per fixed shape, not inherited as magic constants.
3. **Never hand-roll wide SIMD over elementwise glue** — measured ~5× slower than LLVM autovectorization. Hand-SIMD is reserved for int8 MAC micro-kernels and (measured, gated) vectorized transcendentals (§6.12).
4. **Apple AMX is not directly programmable** — the no-FFI Mac path is NEON SDOT/SMMLA; Accelerate/BNNS is an opt-in FFI feature, never the default. **And on Apple Silicon, measure LLVM-autovec against forced SDOT/SMMLA per shape** — franken_ocr's shipped dispatch found autovec *faster* for some ordinary dense int8 shapes on M-series; we inherit the "measured-faster wins, hardware capability is not a routing decision" rule.
5. **AVX2's common `vpmaddubsw` shortcut can saturate inside each adjacent-pair operation** — no later “split-accumulate cadence” repairs already-clipped bits. The Zen 3 path therefore uses one of the exact decompositions in §6.5, selected by measurement and proved against i64.

**What frankentorch does NOT give us (the build list):** the tiled register-blocked int8 GEMM (both prefill GEMM and batched-GEMM), all int4 (packing, in-register unpack→MAC, group scales), the decode GEMV attention over a 44-deep KV, RoPE, the loop scheduler, batched layer-major execution, prefix-cache/KV management, logit-sliced lm_head, samplers, the SentencePiece tokenizer, the chat-template builder, the constrained-decode engine, and the entire task layer. That is the project.

### 3.3 Why asupersync is the execution foundation

The sibling layered pattern is adapted with an explicit process-shared asupersync lifecycle. At the inspected pin, asupersync itself lists Rayon only under `dev-dependencies`; its release surface does not force a Rayon scheduler into FrankenNLP. The offending release edge is `ft-kernel-cpu`'s unconditional Rayon dependency, which Phase 0 must remove or bypass through a narrow no-spawn FrankenSuite leaf surface:

- **`fn main()` stays SYNCHRONOUS** — clap parse, install the asupersync-owned shutdown/signal controller, call sync `run(cli)`, map typed errors → exit codes. The runtime lives below the public API in process `EngineResources`; it is not created per call and is never exposed as the library contract.
- **The target contract is one process-owned asupersync runtime/admission/memory domain; engines hold leases to it.** The default `NlpEngine::builder()` snapshots configuration and acquires an `Arc<EngineResources>` from one documented `OnceLock` broker. The first initialization fixes resource-host fields (runtime preset, effective compute-team width, blocking width, aggregate process memory ceiling); a later incompatible request fails with a field-level `ResourceConfigConflict` instead of silently creating another host or inheriting surprising values. “Runtime preset” means the pinned builder's actual profiles — `current_thread` (one-shot CLI / deterministic-first), `low_latency` (interactive generate), `high_throughput` (batch daemon) — selected per entrypoint and recorded in telemetry, not guessed. The host also fixes the deliberate control-knob posture where the pinned surface provides it (OQ-35 census): bounded blocking-pool min/max (the `spawn_blocking` pool the seam requires anyway), root-region limits as the admission-domain guardrail (never a substitute for service-level backpressure), deadline monitoring with meaningful checkpoint messages surfaced through `robot health`, bounded cancel-attribution depth so cancellation storms stay cheap, and an explicit obligation-leak response policy — leaks panic in lab/CI and are logged-with-escalation in production, never silently ignored. Config layering follows §8.5: code defaults, then the CLI's one-time `FNLP_*` snapshot; the library never reads ambient environment. Advanced callers may install that one process host before the first engine; arbitrary public construction of a second host is not exposed (tests get an isolated `cfg(test)` constructor). Creating ten engines therefore does not create ten runtimes or compute teams. Public methods are sync and blocking. A call made from one of the same runtime's worker threads fails fast with a typed `ReentrantCall` error instead of nesting `block_on`; async hosts call the blocking API from their own blocking boundary.
- **Every admitted request or finite batch epoch has one owned asupersync region and child `Cx`.** That region owns its input feeder, timers/budgets, `spawn_blocking` wrapper task, streaming/result tasks, and drain; no async child, callback, or download is detached. The pinned blocking contract has one explicit physical-lifetime exception: a pool closure already running may outlive its cancelled wrapper. Such a closure is never untracked—it stays registered in `EngineResources`' actual-completion set and retains its admission/memory/output guards until its latch fires, while region/process shutdown treats that set as outstanding drain work. Phase 0 must ratify whether the request region itself can remain draining until the latch or whether the process supervisor owns that final join; either route is explicit in receipts and tests. Process lifetime otherwise owns only the reusable runtime/resource host and bounded daemon supervisor, never semantic request state. This is the structured-concurrency authority behind the synchronous library facade.
- **Authority narrows with the dataflow.** The inspected pin exposes a sealed type-level capability row `[SPAWN, TIME, RANDOM, IO, REMOTE]`, runtime masks, and monotone `Cx::restrict`; widening after restriction is a compile-time error **[OBSERVED@pin]**. Phase 0 ratifies project aliases and compile-fail tests, but the intended least-authority split is fixed now: pull/source acquisition gets only the spawn/time/IO and TLS entropy demonstrably required by the pinned client, never REMOTE; ordinary admitted inference has no network/remote authority; caller-supplied seeds make sampling deterministic data, while an unseeded sampling admission may draw entropy exactly once and then pass owned RNG state; greedy decoding has no RANDOM authority; and a leaf shard receives `cap::None` or an equivalently narrow project checkpoint view, never IO/REMOTE/RANDOM or permission to spawn. Synchronous model-file access is an explicit admission/load boundary rather than ambient kernel authority. `Cx::current()` is not an escape hatch: runtime restrictions and a policy test must show an ambient lookup cannot regain dropped effects.
- **Resource discovery is capability-scoped, not a hidden fourth dependency.** Logical parallelism may fall back to `std::thread::available_parallelism`, but physical-core/topology, cgroup/job-object-aware memory, NUMA placement, huge-page advice, and Apple QoS require a pinned safe FrankenSuite surface whose semantics are ratified in Phase 0. FrankenNLP never reaches through to a transitive `sysinfo`/`libc` crate. If trustworthy memory discovery is unavailable, model loading requires an explicit process budget instead of guessing; if topology/placement is unavailable, the portable no-affinity schedule remains correct and `robot health` reports the limitation.
- **Memory admission is process-aggregate, not ten independent promises.** `EngineResources` owns a checked reservation ledger for loaded Generic/native weight buffers, KV/pages, activation/logit scratch, prefix/grammar caches, job buffers, and staging overhead across every engine lease. Exact same-digest read-only weights/native packing may share one `Arc`; every other copy is charged. Each engine may request a lower local ceiling, but the process ceiling remains authoritative. Reservation is two-phase (reserve before allocation, commit after success, abort on failure/cancel), and no engine lock is held while waiting for admission. User-content caches remain engine/namespace isolated even when public immutable weights are shared.
- **CPU-bound stages cross the native asupersync boundary once.** An admitted run enters through `Cx::spawn_blocking`; inside that blocking closure, the pinned `Cx::scoped_cpu(worker_cap, …)` surface creates the bounded lending fork/join team. The pinned `spawn_blocking` implementation has a deterministic inline fallback when its `Cx` carries no blocking-pool handle, so production `EngineResources` must configure that handle and the G0 probe must prove a runtime heartbeat progresses while the coordinator is busy; inline execution is test/lab fallback, never a production success. Scoped children borrow run-local tensors safely, inherit the caller's `Cx`, checkpoint cancellation/budgets at tile or morsel boundaries, contain panics, and all join before the region returns. The scope spans an entire generation request or a **bounded** batch scheduling epoch—never one layer, tile, token, or unbounded daemon lifetime—because creating OS threads per micro-operation would destroy latency while an immortal scope would defeat structured drain and policy updates.
- **Intra-op parallelism is owned by asupersync's scoped CPU region; leaf kernels never spawn.** The blocking coordinator may execute one deterministic shard while creating at most `effective_compute_team_width − 1` children; the Phase-0 probe establishes the exact coordinator/child arithmetic instead of assuming that `worker_cap` includes the caller (the pinned API defines it as a cap on spawned children). The inspected `ScopedCpu::spawn` checks the numeric cap but not the scope's drain latch before creating a child. FrankenNLP therefore uses a sealed formation protocol: create the entire fixed team while workers wait at an entry gate, irrevocably end the spawn phase, then release them into the persistent command loop; no fallible kernel work starts before the seal and the coordinator never calls `spawn` again. A hostile interleaving test proves cancellation/panic cannot produce a post-start or post-latch worker. Exactly one latency forward occupies the admission domain; concurrent library callers wait through a bounded asupersync session/semaphore policy or join a compatible throughput batch. They never create independent oversubscribing scopes. Streaming uses bounded, two-phase channels integrated with the same cancellation/drain state machine — the reserve→permit idiom: acquire a send permit, then place the message, so a cancelled sender cannot half-deliver; a held permit is an obligation and is never carried across an unrelated await — and no user callback runs while an engine/admission lock is held.
- **Foundation adaptation is mandatory, not optional architecture.** The inspected `ft-kernel-cpu` pin makes Rayon unconditional and many entrypoints reach its global pool. Before production kernels consume it, frankentorch must expose the required serial/range leaf functions behind a no-Rayon feature (or an equivalently narrow FrankenSuite leaf crate), with exact tile ownership and no internal spawning. FrankenNLP's release dependency graph must contain no Rayon. Existing Rayon-backed entrypoints may remain out-of-process/reference or development baselines only; setting `RAYON_NUM_THREADS=1` is not a production ownership proof.
- **Cancellation is cooperative, and “cancelled” is not allowed to mean “resources were reused while compute still ran.”** A cheaply cloned asupersync `Cx` (or a narrower checkpoint capability proven by the Phase-0 probe) is threaded into long loops; `checkpoint()` runs at named tile, per-doc, prefill-morsel, and per-decode-step boundaries, and additionally inside long grammar-mask expansions, source-index construction, repacking panels, and download chunks. Every stage declares a **maximum uninterruptible work quantum**; the gauntlet measures p50/p95/p99 cancellation-observation latency under R1–R4 and rejects any stage that can monopolize the process until a whole 200K-token prefill or giant matrix completes. The pinned `spawn_blocking` contract says an already-running closure is not preempted and its task result may be discarded on cancellation. Therefore the actual blocking closure owns the compute-admission lease, memory reservation, output buffers, and a completion latch until its `scoped_cpu` region has joined and the closure exits. The synchronous API does not report drain complete or reuse those resources merely because its `TaskHandle` resolved cancelled. Per-doc budgets prevent one pathological document from stalling the stream. `Cx` is **Clone, not Copy**, at the inspected pin.
- **Outcome fidelity survives orchestration.** The pinned foundation's `Outcome::{Ok, Err, Cancelled, Panicked}` severity lattice is retained through child join, region drain, actual-completion-latch resolution, and the library/CLI policy boundary. Adapters may attach context, but they do not flatten cancellation or panic into a generic application error early; the public synchronous API then maps the four states deliberately to typed errors, exit codes, diagnostics, and retry authority.
- **Capacity certificate:** bounded channels everywhere (backpressure, never unbounded growth); a gauntlet artifact proving one owned request/epoch region with no untracked children or leaked obligations, every post-wrapper-cancel pool closure tracked to actual completion, one admitted scoped team, exact coordinator/child width, effective worker cap, no production dependency or escape to a Rayon/global pool, bounded checkpoint latency, full join on cancel/panic, region-close quiescence, and no nested-runtime/team oversubscription; the `many_docs_without_deadlock` CI watchdog (batch of docs ≫ compute width) hangs on regression. Asupersync LabRuntime/oracles cover runtime tasks, regions, obligations, cleanup, futurelock, and quiescence; they do **not** enumerate the native OS-thread interleavings created inside `scoped_cpu`. The scheduler proof therefore combines Lab reports with a repository-owned bounded abstract team-state model and hostile native stress/replay around the sealed formation gate, latches, and capacity-1 lanes.

> **Hard rule (the deadlock saga's durable fix): NEVER enter `spawn_blocking`/`scoped_cpu` while holding an engine lock; NEVER recursively create a scoped CPU team; NEVER nest a second asupersync runtime inside a task; NEVER let a leaf kernel spawn work; NEVER release a compute or memory lease on wrapper-task cancellation before the blocking closure's completion latch fires.** One process admission domain; the outer request loop is sequential (latency mode) or explicitly batch-scheduled (throughput mode); a forward fans out only inside its single admitted asupersync scope.

### 3.4 FrankenSuite dependency policy

The exact sibling commits in the research snapshot become a checked `SUITE.lock`-style manifest before Cargo scaffolding; floating `0.3.x` prose is not reproducibility. The toolchain is an **exact dated nightly** selected in Phase 0; floating `channel = "nightly"` is forbidden, and CI records and checks `rustc -Vv`, LLVM version, target triple, and enabled target features. `SUITE.lock` also records every root-level `[patch]`/source replacement in the pinned FrankenSuite repositories, because **Cargo does not inherit a dependency repository's root patches** (the pinned frankentorch root carries a `[patch.crates-io]` entry for `block` that would silently vanish when frankentorch is consumed by Git revision). Phase 0 computes the actually selected release feature graph, determines which reviewed root patches are relevant to it, mirrors required patches into the FrankenNLP root manifest at exact revisions, refuses irrelevant or stale copies, and fails CI when a pinned suite root changes its patch closure without a plan revision; the generated `SUITE_ROOT_PATCHES.lock` is cross-checked against `cargo metadata`, `cargo tree -e features`, `Cargo.lock`, and the root `Cargo.toml`. The **committed public Cargo manifest uses immutable Git revisions** for FrankenSuite dependencies so a fresh clone builds without the maintainer's sibling-directory layout; `Cargo.lock` and `SUITE.lock` must agree. Local `/dp` or `~/projects` checkouts may be selected only through an untracked developer override, and a preflight refuses the override unless its HEAD equals the reviewed pin. No absolute/local path enters a release manifest. Direct FrankenSuite dependencies are layer-minimal: `ft-kernel-cpu`, `ft-core`, `ft-serialize`; `asupersync` with only the runtime/network/TLS features actually used; and optional `fsqlite`/`fsqlite-types` for metadata/job state. The asupersync workspace additionally contains FrankenSuite substrate crates — `franken_kernel` (type substrate), `franken_evidence` (evidence-ledger schema), `franken_decision` (decision-contract runtime), and `frankenlab` (deterministic test harness) — that are pinned suite surfaces, not commodity dependencies; the OQ-35 census audits whether the pinned revision's versions usefully serve the §9.7 registries, the §7.8 `DecisionPolicy` contract, and the deterministic test program, and adopting any of them is an explicit `SUITE.lock` decision recorded in this plan, never a silent import.

The **complete direct non-FrankenSuite release allowlist is exactly three families**, approved by the project owner on 2026-07-30:

1. `clap` — CLI parsing only;
2. `serde` + `serde_json` — typed API/NDJSON/schema/manifest data only;
3. `sha2` — SHA-256 artifact/provenance integrity, canonical semantic ids/addressed sampling, and the RFC-tested HMAC-SHA-256 pseudonym primitive.

No `thiserror`, `anyhow`, `ctrlc`, `rayon`, `half`, `memmap2`, `uuid`, `num_cpus`, allocator crate, or other commodity crate may be added. Typed errors use `std`; shutdown/signals, bounded tasks, HTTP/TLS, CPU-team lifecycle, and bf16/safetensors come through the pinned FrankenSuite surfaces; local audited islands are SIMD and opt-in mmap only; NUMA/topology/QoS/huge-page controls require a safe pinned suite surface or remain off; stable ids derive from canonical hashes. Mmap, `madvise`, huge pages, NUMA placement, QoS, file locking, owner-only permissions, Windows ACLs, and peer-credential local IPC are **not licensed merely by calling them “audited islands”**: Phase 0 creates `docs/PLATFORM_SURFACES.md` listing, per target, the exact API/ABI authority, whether `std` or a pinned suite crate exposes it, any manually declared symbols, minimum OS/ABI version, safety invariants and fallback, and the feature/subcommand blocked when no approved portable surface exists. No handwritten platform ABI enters release code to preserve the three-family dependency slogan; an unavailable reviewed surface disables the optimization or refuses the operation rather than silently weakening ACLs, locking, or memory safety. A dependency-policy test parses `Cargo.lock`/`cargo metadata` and fails if a new **direct** non-suite root appears. Transitive dependencies already selected by a pinned FrankenSuite crate or the three approved roots are recorded in the supply-chain manifest; they are not permission to depend on them directly. **Rayon is a stricter exception: because it would create a second ambient scheduler, it must be absent from the FrankenNLP release graph, not merely absent from direct dependencies.** Benchmark/oracle tooling stays outside the release dependency graph.

**No `tokenizers`, `tiktoken`, `minijinja`, `llguidance`, ONNX, torch, BLAS, or C tokenizer/grammar library.** Asupersync's inspected tree contains `RuntimeBuilder`, `Runtime`, `ShutdownController`, HTTP client modules, and the `tls-webpki-roots` feature; Phase 0 proves the exact selected feature closure with an HTTPS range-download fixture matrix before `fnlp pull` depends on it. That matrix must settle and document: webpki-bundled versus platform trust roots; `HTTPS_PROXY`/`HTTP_PROXY`/`NO_PROXY` behavior; private-mirror authentication input and redaction; redirect host/scheme policy and cross-origin credential stripping; TLS name validation and minimum protocol; `Accept-Encoding: identity` for range/length-authenticated assets and rejection of unexpected content encodings; exact `206`/`Content-Range`/body-length semantics; IPv4/IPv6 and DNS failure behavior; and enterprise/private-CA support or an explicit unsupported statement. No README claims proxy or enterprise-CA compatibility before these fixtures pass (OQ-33). The only product network path is the explicit pull command. The tokenizer bytes (Apache-2.0, attribution carried per §5.7) are embedded in the binary so `fnlp tokens`/`split` and grammar compilation work before any artifact is installed; the engine hash-checks the embedded copy against the artifact's tokenizer blob at load (mismatch = loud census error).

### 4.2 In-crate subsystems that franken_ocr did not need (build-fresh list)

- **SentencePiece tokenizer (`tokenizer/`)** — parse `tokenizer.model` (a protobuf; we write a minimal, dependency-free reader for the pieces/scores/type fields — same discipline as franken_ocr's in-crate HF-JSON BPE — whose accepted field set, unknown-field skipping, varint length, nesting, allocation, piece-count, string-length, and total-byte limits are specified and fuzzed; unterminated varints, overflow, conflicting duplicate singular fields, and invalid UTF-8 reject cleanly), implement the observed SentencePiece **BPE** merge/scoring semantics, byte-fallback behavior, special-token injection, and exact decode (including whitespace/replacement conventions). Token-id-exact vs the slow reference tokenizer is gate L0 (§9.2); OQ-6 retains edge semantics, not the model-family choice.
- **Chat-template builder (`template/`)** — a typed Rust builder over the exact pinned `Conversation`, `Message`, `MessageContent`, `ContentPart`, `AssistantReasoning`, `ToolDefinition`, `ToolCall`, and `ToolResult` forms (§2.5 AST) that reproduces `apply_chat_template` byte-exactly across the complete accepted mode matrix and cleanly rejects every unsupported form. The fixture matrix (OQ-7) explicitly covers content arrays, media-reminder branches, default system text, non-leading system messages, adjacent tool responses, prior-turn thinking preservation/removal, both tool formats, and empty/malformed fields. No Jinja interpreter — the template is one fixed program; we implement *it*, not a template language.

- **Task layer (`tasks/`)** — §7; built-ins first compile to a bounded, non-executable `TaskIR`; the public recipe format stays closed until equivalence, resource, and no-code/no-network gates pass.
- **Batch scheduler (`batchsched.rs`)** — §6.7.
- **Durable corpus jobs (`jobs.rs`)** — §8.4; opt-in fsqlite journal + content-addressed semantic keys + checksummed spool/materialization, with no input/output persistence by default.

### 4.3 Pipeline stages (composable, budgeted, cancellable)

```
Resolve model → Load/mmap .fnlpq (census-checked) →
  Tokenize (template build | raw) → [grammar compile, cached] →
  Prefill (batched, prefix-cache aware) → Decode loop (constrained | free) →
  Detokenize / parse → Task postprocess (validate, offsets, calibrate) → Emit (json | ndjson | text)
```

Every stage receives a typed child `RequestBudget`; it does not read process environment. The CLI may snapshot `FNLP_STAGE_BUDGET_<STAGE>_MS` into `NlpEngineBuilder`, while embedders set the same field directly. Child budgets are a monotone meet with the parent and may only tighten it. They combine the pinned asupersync `Budget` dimensions (absolute deadline, poll quota, cost quota) and `CapabilityBudget` dimensions (memory bytes, CPU units, IO bytes, cleanup budget, evidence-artifact bytes) with engine-owned semantic counters for input/output tokens, grammar states, KV pages, batch rows, and emitted bytes. Required missing or exhausted dimensions fail closed before allocation; cleanup retains a separately reserved nonzero budget so cancellation can drain rather than consuming the last unit and stranding obligations. Each long stage also declares its maximum uninterruptible quantum and checkpoint cadence. A Phase-0 executable probe freezes the exact mapping from project units to asupersync cost/capability units; until then, no prose treats milliseconds as a complete resource budget. The two cost centers are **prefill** (compute-bound; dominates scoring/classification workloads where outputs are tiny) and **decode** (memory-bound; dominates generation/summarization). They are profiled and optimized separately, per regime (§10.1) — the cost-center split is the same discipline as franken_ocr's vision-vs-decode split, with prefill playing vision's role.

### 4.3.1 Canonical execution identity and compatibility

One canonical, versioned **`ExecutionIdentity`** value is constructed before admission and reused by task envelopes, prefix/grammar caches, durable jobs, qualification receipts, benchmarks, and ledgers. It contains: `source_revision`, `logical_model_sha256`, `artifact_format`, `quant_recipe`, `packing_set_sha256`, `tokenizer_sha256`, `template_sha256`, `task_spec` + `taskir_sha256`, `prompt_sha256`, `grammar_compiler_version` + `schema_sha256`, `numerics_profile` (§1.1.1), `kv_dtype`, `sampler_version`, thinking/tool mode, `calibration_sha256`, `decision_policy_sha256`, `backend_semantic_version`, and — where `fast-vN` semantics require it — `host_class` and `compiler_identity`.

Subsystems derive domain-separated keys from this one structure; they may not manually assemble partial lookalikes, which is how a cache key eventually omits thinking mode, grammar version, calibration, or packing semantics. Artifact/release receipts additionally bind a separate canonical `ProvenanceIdentity` containing `source_root_sha256`, `fnlpq_file_sha256`, `release_manifest_sha256`, `license_bundle_sha256`, converter/build provenance, and publisher-attestation status. Legal-notice bytes are intentionally **not** part of `logical_model_sha256` or semantic cache authority: correcting a modification notice must not pretend the model computation changed. `docs/COMPATIBILITY.md` states which field changes invalidate each cache, receipt, golden, calibration artifact, and job stage; a property test mutates every field in turn and asserts the documented invalidation behavior. The §6.7 prefix-cache key, §8.4 semantic job key, and §9.7 receipt identity are all named projections of `ExecutionIdentity`; release/legal verification uses `ProvenanceIdentity`.

## 5. Weight transformation pipeline

The mandate: **immutable pinned HF snapshot → reference-parity load → custom quantized form → deterministic round trip → distribution with license/attribution carried → verified local activation**. There are two deliberately separate download paths:

1. **Sovereign/source path:** a maintainer or user explicitly downloads the pinned 8.34 GB upstream checkpoint, verifies it, and runs `fnlp convert` locally. This path is always complete on its own.
2. **Release/install path:** maintainers publish the already-converted canonical `.fnlpq` as immutable GitHub Release chunks; `fnlp pull` reassembles and activates it on the user's machine. The installer invokes that same Rust pull path—it never downloads or converts the upstream bf16 shards itself.

### 5.2 Custom on-disk format `.fnlpq`

Adapt the `.focrq` container pattern, with a newly specified strict envelope rather than ABI-by-analogy:

```
fixed prelude (canonical little-endian):
  magic: b"FNLPQ\0\0\x01"                     # valid Rust byte literal; eight bytes
  format_version / required_flags: u32
  header_len / section_count / tensor_count / file_len: u64
  header_sha256: [u8; 32]

canonical header JSON (exactly header_len bytes, hash-checked before parsing):
  arch_target: Generic | Aarch64Sdot | Aarch64I8mm |
               X86Vnni256 | X86Vnni512 | X86Avx2
  source_files: [{name, len, sha256}]          # ordered provenance
  recipe_id / converter_commit / census_digest / source_root_sha256
  logical_model_sha256 / packing_set_sha256 / license_bundle_sha256
  sections: [{id, kind, absolute_offset, len, sha256, alignment}]
  tensors: [{name, dtype, shape, data_section, data_offset, data_len,
             scale_section?, scale_offset?, scale_len?, group_size?, tier?}]
  bit_allocation_table? / packing_manifest / frozen relevant config fields

ordered binary sections:
  tensor bytes + scale/row-sum metadata
  exact tokenizer.model bytes
  exact tokenizer/config/template source bytes
  Apache-2.0 + attribution + modification-notice bundle
```

- The prelude/header/section table is the authority for ranges; JSON never carries raw binary blobs and no base64 dependency exists. Every section has one kind, absolute range, alignment, and digest. Ranges are checked with `u64` arithmetic against `file_len` and the actual file, must not overlap the prelude/header or each other, and may leave only explicitly declared zero-filled alignment gaps. Required tokenizer/template/license section kinds occur exactly once. Caps cover section/tensor count, rank, each dimension, header/config/template/tokenizer/license size, and total mapped bytes. Unknown required flags/enums reject; no “best effort” parsing of a newer format.
- **Canonical bytes are specified, not delegated to an unspecified map serializer.** Authority-bearing names/ids/filenames are restricted to explicit printable-ASCII grammars (tensor dotted names, lowercase recipe ids, portable single-component filenames), so the format does not need an unapproved Unicode-normalization library. Free-form upstream template/license/attribution material is retained as exact hashed bytes in typed sections. The header writer uses fixed Rust structs plus sorted lists/`BTreeMap` only where the schema declares key order; duplicate keys/names reject; JSON strings use one pinned UTF-8 escape form; integers/digests carry authoritative numeric/byte values; floating scales live in binary sections with fixed IEEE-bit encoding, not JSON numbers; NaN/Inf reject; padding is zero; and the canonical writer never accepts arbitrary `serde_json::Value` maps. A golden serializer fixture covers every field, escape, order, alignment gap, and section kind.
- Prelude validation happens before any variable allocation: magic/version/flags must be known; declared `file_len` must equal the actual regular-file length; `header_len` must fit a compile-time hard cap and checked `prelude_len + header_len`; and counts are not trusted until the bounded header hash and canonical parse succeed. `header_sha256` therefore detects header corruption before allocating from attacker-controlled section/tensor counts. The **digest taxonomy is normative**: `source_root_sha256` (canonical ordered source-file identity) · `logical_model_sha256` (domain-framed over ordered logical tensor `(name,dtype,shape,canonical logical bytes)` records plus exact materialized config/tokenizer/template identities — the packing-independent computational model identity; the ambiguous bare name `semantic_digest` is retired) · `packing_set_sha256` (the exact representation/layout set) · `license_bundle_sha256` (exact license, attribution, upstream notices, and modification-notice section bytes; legal/provenance identity, never model semantics) · `fnlpq_file_sha256` (exact complete file bytes, the externally manifested physical identity) · `release_manifest_sha256` (exact canonical manifest bytes). Native repacking changes `fnlpq_file_sha256`/`packing_set_sha256` without changing `logical_model_sha256`; a notice-only correction changes `license_bundle_sha256` and the complete file/release identities without claiming a new computational model. Header/section digests permit a fast bounded structural check; `fnlp models verify --full` is the explicit bit-rot recheck, and the activation receipt always binds the full-file digest verified at installation.
- Quantized tensors carry inline scales (per-out-channel int8; per-group int4 + tier metadata), with exact expected scale counts derived from shape and group size. NaN/Inf/non-positive scales, overlapping ranges, duplicate names, misalignment, and non-canonical nibble padding reject.
- High-precision tensors stored **BF16 verbatim** (byte-identical round-trip; the bf16-not-f16 rule inherited — f16 narrowing is lossy and only ever a ledgered divergence).
- Reader = checked byte-range index over one owned buffer (default) or the opt-in `FNLP_MMAP=1` mapping (audited island); only the approved serde/JSON metadata layer sits above the binary envelope. Census plus logical-model-digest verification runs on load so wrong/stale weights fail loudly before any kernel sees a pointer.
- An arch-specific artifact never silently “falls back” to a different packing. A `Generic` artifact may be deterministically derived into a separate arch cache; an incompatible arch target is a hard error naming the required derivation. A `PackingSet` may contain multiple representations only when the duplicate byte cost is explicit, and dispatch may select only a kernel whose required representation is actually installed — per-shape dispatch cannot assume mutually incompatible SDOT/I8MM/VNNI/AVX2/autovec layouts all exist for free. `fnlp tune` may atomically derive, benchmark, and activate a new packing set from Generic, but cannot write a dispatch row referencing a missing representation; its objective includes added disk bytes, mapped bytes, load time, and cache pressure, not only microkernel latency.

### 5.4 Determinism & round-trip story

- **Bit-exact round-trip** for BF16 tensors (convert→load→re-serialize asserts byte equality).
- **Deterministic quant is a target with a cross-target gate (`portable-quant-v1`), not a prose assumption:** pure function of ordered source-file bytes + versioned recipe. BF16 decoding, absolute-value/max behavior, NaN/Inf rejection, rounding mode (round-to-nearest, ties-to-even), negative-zero handling, zero-row behavior, scale precision, clamp domain and order, f32 operation order with no contraction and no fast-math or host-approximate conversions, int4 nibble order, group traversal, serializer order, and padding bytes are specification. CI converts the same fixture on every supported OS/ISA and compares the complete Generic digest. If full-model cross-target identity fails, release tooling designates one pinned canonical publisher target and local conversion claims semantic/quality equivalence—not hash identity—until the cause is removed. If an eval/calibration set enters AA-Q1, its license, digest, order, preprocessing, and split ids join the recipe.
- **Canonical algebra:** logical activations and weights are signed i8. Per-channel int8 computes `y[o] = bias? + sx * sw[o] * Σk(qx[k]·qw[o,k])` (there are no model biases; the notation reserves the contract). VNNI consumes `u8×s8`, so x86 forms `u = qx XOR 0x80` and exactly subtracts `128·Σk qw[o,k]`, with row sums stored in the packing metadata. Per-group int4 computes and dequantizes a separate i32 accumulator for each group, then adds groups in a specified increasing-group f32 order; scales may not be pulled outside that sum. Every SIMD path preserves this logical reduction order.
- **Overflow proof (recomputed for this model and every materialized intermediate):** at K=10752, full-domain S8×S8 ≤ 176,160,768; raw U8×S8 ≤ 350,945,280; `|128·Σw|` ≤ 176,160,768; even the conservative independent raw-plus-correction bound is 527,106,048, inside i32. Int4 group accumulators have their own much smaller bound. Compile-time formula tests cover every model K; runtime kernel tests use exhaustive small-K pairs plus adversarial full-K vectors and compare every tier to an i64 oracle.
- **One canonical logical artifact, many derived packings:** `fnlp convert` emits `--arch generic` only. `fnlp models derive --arch {aarch64-sdot,aarch64-i8mm,x86-vnni256,x86-vnni512,x86-avx2}` creates a disposable content-addressed native cache from that Generic root; packing ids also include the tile-table version. CI verifies every derived packing reconstructs identical logical weights. A maintainer packaging command cannot accidentally publish a native cache as the canonical artifact.

### 5.5 Quantization recipe rationale (what's validated vs what's ours to prove)

Unlike franken_ocr (which inherited a community-validated recipe), the available prior is the official/historical GGUF K-quant lineage **[REPORTED]** — evidence that Q4_K_M-class works for chat, but with no published per-tensor sensitivity for *this* architecture and no task-level accuracy data. So the recipe is **ours to establish by measurement**:

- **int8-everything-quantizable first** (Phase 2, staged 2a/2b/2c) as the near-lossless correctness oracle; expected ≈ 4.7 GB with bf16 embed (§13).
- **int4 by allocation, not uniformity** (Phase 5): begin with uniform deterministic recipes as baselines, then let the offline AA-Q1 allocator (§10.5) choose per-tensor tiers under a footprint budget against **held-out task metrics**, not perplexity alone. Hypotheses informed by llama.cpp `_M` recipes—such as higher precision for `down_proj` or early/late layers—remain hypotheses. The loop reuses each quantized tensor in both passes, so sensitivity interactions are joint: one-at-a-time tensor curves may seed search, but only a complete candidate artifact evaluated end-to-end may be promoted.
- Embeddings/lm_head int8 are separate measured **artifact stages** (immutable recipes per §5.1[3]); KV int8 is the one genuinely runtime-gated quantization choice because KV is produced at run time (§6.8).

### 5.6 GitHub-asset distribution, `fnlp pull`, and installer handoff

This section deliberately copies FrankenOCR's **proven invariants**, while correcting its historical rough edges: versioned immutable filenames, a release-bound embedded manifest, exact recipe compatibility before any multi-GB request, streamed part/whole hashing, cache discovery that recognizes the installed basename, per-artifact locking, same-directory staging/rename, and clean-cache inference certification.

#### 5.6.1 Canonical artifact and independent model version

- The canonical arch-neutral Generic `.fnlpq` is published as a versioned model release. Binary SemVer and model-artifact SemVer are independent: e.g. several `fnlp` `v0.x.y` binaries may consume immutable model release `models-nanbeige42-fnlpq-v1`. A patch binary release must not rename or republish identical 4+ GB bytes.
- The logical filename is artifact-version/quant/packing-bearing: `nanbeige4.2-3b.fnlpq-v1.int8.generic.fnlpq`; the exact recipe id is authoritative in the manifest and container header. A different source revision, format, recipe, tokenizer/template closure, or logical bytes gets a new artifact version/name/tag; bytes under an existing tag/name are never replaced.
- Public hosting stays 1× per quant tier. The released artifact is Generic; `fnlp pull` derives the host's measured-default packing locally (M4/M5 SDOT/I8MM candidate, Zen 3 AVX2, Zen 4/5 VNNI-256/512 candidate) and caches it by `(whole_artifact_sha256, packing_id, tile_table_version)`. Capability alone never decides the winner. Generic remains the reconstruction/provenance root; the derived cache is disposable and byte-differential-tested against its logical tensors. **Local steady-state disk is not 1×**: it holds canonical Generic plus the active derived packing plus small receipts. `fnlp pull`, the installer, `robot plan`, and every footprint claim report five quantities — network download bytes, canonical Generic bytes, derived packing-set bytes, peak install bytes (staging plus any previously active artifact), and steady-state retained bytes. `--no-native-cache` retains only Generic on its compatible slower path; any future `--prune-generic` must state that repacking, provenance replay, and some repairs will require redownload, and is never a silent default.

#### 5.6.2 Deterministic chunking and release inventory

- The release packager splits the exact `.fnlpq` byte stream into **1,957,046,720-byte** chunks, with only the final chunk shorter—the exact safely-under-2-GiB size proven in FrankenOCR. Names append zero-padded ordered suffixes `.part00`, `.part01`, …; the manifest caps the count (64 in v1) so two digits are sufficient and unambiguous. Concatenation in manifest order is the original file; there is no archive or compression layer.
- A canonical schema-versioned manifest records: model/artifact ids; immutable release tag; logical filename/length/SHA-256; exact ordered part name/length/SHA-256/HTTPS mirror URLs; ordered source-file digests and source-root digest; recipe/converter/format compatibility; tokenizer/template/census/logical-model/packing digests; license-bundle digest; packing policy; revocation/supersession state. The canonical manifest bytes and SHA-256 are embedded in every compatible binary and also attached to the model release for audit. Default pull never fetches manifest identity from `main`, `latest`, or another mutable branch.
- Manifest URLs are stable, immutable release-tag URLs (`releases/download/<exact-tag>/<asset>`), not captured expiring object-storage redirects. Redirect targets are validated at request time.
- The staging directory also contains `MODEL_ASSET_RECEIPT.json`, `SHA256SUMS`, `RECONSTRUCTION.txt`, and the exact approved license/NOTICE/modification bundle. The receipt binds the conversion receipt, split command/tool version, ordered reconstruction, whole result, parity/quality receipts, and intended release inventory. These small records are committed or attached; the multi-GB `.fnlpq` and parts remain gitignored.
- **Hashes prove byte integrity, not publisher identity.** The embedded manifest is trusted only relative to the installed binary. The release workflow therefore emits GitHub artifact attestations for five subjects: every platform binary; the binary SBOM; the canonical model manifest; the conversion/packaging receipts; and either the complete canonical `.fnlpq` subject digest or every published part plus the manifest-bound reconstruction digest. Published instructions show `gh attestation verify … -R Dicklesworthstone/franken_nlp` as the optional publisher-provenance check (online by default; offline only with a separately retained verification bundle and a proven supported workflow). This adds no runtime dependency and does not pretend a checksum sidecar fetched beside a file is a signature.
- Publication uses a **draft** GitHub Release and exact explicit upload paths—never a wildcard, never `gh release upload --clobber`. The runbook first hashes the retained staging set, reconstructs it, and compares the whole bytes with the converter output. After upload, it queries the remote inventory, downloads each asset through its public URL into a clean directory, repeats part/whole verification, verifies attestations, runs a clean-cache `fnlp pull`, derives the native packing, runs `robot selftest`, and reproduces a frozen real-model inference fixture. Only that receipt authorizes publishing the draft. A bad release is superseded by a new catalog; immutable old bytes are not rewritten. **Revocation is not recall:** an old offline binary with an embedded old manifest may still install an old immutable release, so revocation takes effect only after the user installs/uses a newer trusted catalog or binary. `fnlp models` reports this limitation and never claims old bytes vanished.

#### 5.6.3 One Rust artifact manager

`fnlp pull [--quant int8|int4] [--arch auto|...] [--model-dir ...]` and the installer share exactly one implementation: the installed `fnlp` binary's Rust artifact manager over asupersync HTTP/TLS. `install.sh`/`install.ps1` never parse the model manifest, concatenate chunks, or maintain their own hash/cache rules. This prevents the binary and installer from disagreeing about recipe, filename, cache layout, or integrity.

- Default manifest = release-bound embedded bytes. `--manifest <local-path-or-https-url>` is the sovereign/private-mirror escape hatch and **must** be paired with `--expected-sha256`; `FNLP_MANIFEST_URL` is not a hidden library read. HTTPS authenticates the transport endpoint. The expected digest binds the manifest **only to the extent the caller obtained that digest through a trusted channel**; a manifest and digest supplied together by the same attacker prove only self-consistency. Its part/whole digests then bind content. Redirects are host-allowlisted and credentials are never forwarded cross-origin.
- Before any artifact request, the parser enforces exact schema/recipe/format compatibility, portable single-component filenames, unique case-folded names, canonical part ids/order, HTTPS URLs, checked part-size sum, count/size/string caps, and required license/census digests. An incompatible historical recipe fails before cache creation or network I/O.
- The manager streams response frames directly into one same-filesystem staging file while updating per-part and whole SHA-256; a part is never buffered in RAM. Each mirror attempt rolls back to the last verified part boundary. Where the OQ-35 census ratifies them at the pin, transient-failure retries use the foundation's budgeted retry combinator with a **total** retry budget (never unbounded per-attempt sleeps), mirror selection uses `first_ok`-style racing with losers drained, and staging/activation release paths use `bracket`-style guaranteed-release composition; absent ratification, the hand-rolled equivalents implement the same explicit budget/drain semantics. A small resume journal binds the manifest digest, final path, committed length, and verified part index. On restart, the manager rehashes every committed part before trusting the prefix. Intra-part Range resume is used only after an asupersync fixture proves `206` plus exact `Content-Range`; otherwise the unverified tail is truncated and that part restarts.
- **Filesystem transaction contract:** the model root must be owner-controlled and not writable by an untrusted principal. The pinned nightly must pass a Phase-0 probe for `std::fs::File::{lock,try_lock}` and platform rename/directory-durability behavior. One non-reentrant lock handle guards each content address; staging and activation records use `create_new`; all temporary and final paths remain on one filesystem; symlink/reparse/device targets and hostile parent permissions reject. Where safe handle-relative/no-follow operations are unavailable, shared/adversary-writable roots are unsupported rather than papered over with a racy pre-check.
- Existing files count as cached only after exact length + whole SHA-256. After all parts verify, the manager syncs and fully parses/census-checks the staged `.fnlpq`, verifies its embedded source/license/semantic identity, derives the native packing through its own resumable `create_new` staging transaction, differentially checks it, and runs required selftests. It syncs staged files and renames each to a previously nonexistent content-addressed destination on the same filesystem; it never depends on `rename` replacing an existing file, which is not portable to Windows. Activation is an append-only commit journal: under the model-root lock, construct a canonical record body containing checked monotonic sequence, artifact/native/config digests, and previous-record digest; compute `record_digest = SHA-256("fnlp-activation-v1" || body)`; write/sync a `create_new` staged envelope containing body + digest; rename it to a unique sequence-and-digest final name; then sync the directory where supported. Discovery recomputes every digest and follows the one contiguous chain from the unique genesis. Staged/torn/gapped/disconnected records are ignored; two valid successors of one head are an `ActivationFork` integrity error, and discovery retains only the last unambiguous head rather than choosing by filename or digest. Activate and rollback both append a new record—neither overwrites the old pointer or artifact. Failure, cancellation, disk-full, crash, or a malicious mirror therefore leaves the previously active chain head intact. Concurrent pulls converge on the same content address.

## 6. Model-specific CPU kernel strategy

### 6.1 The hot ops (profile-anchored hypothesis — to be REPLACED by measured profiles before any kernel lands)

| Op | Regime | Bound | Priority |
|----|--------|-------|----------|
| MLP GEMV ×3 ×22 ×2 loops (2.18 B unique weights; **4.36 B weight-MACs/token**) | decode | memory | **HIGHEST** |
| Attention q/k/v/o GEMV ×22 ×2 (0.97 B unique; **1.94 B weight-MACs/token**) | decode | memory | **HIGH** |
| lm_head GEMV (510 M, or **sliced ~kB-scale** §6.10) | decode / scoring | memory | **HIGH** (or ~free when sliced) |
| Decode attention over 44-deep KV | decode, grows with ctx | memory | **MED-HIGH** |
| Prefill GEMMs (same weights, token-parallel) | prefill / scoring | compute | **HIGH** (scoring throughput = this) |
| Prefill SDPA (48:8 heads, causal) | prefill, O(T²) | compute | **MED** (short-doc regime), **HIGH** ≥ 8K |
| RMSNorm / RoPE / SiLU / softmax / residual | both | mem/compute | **LOW** (autovectorize; fuse) |
| Embedding row gather | both | memory | **LOW** |

Cost model per §2.6: a decoded token logically reads ≈ 3.7 GB of weights (int4+int8 recipe) — decode is overwhelmingly weight-bandwidth-bound at batch 1, which is exactly why §6.7's batching is a structural, not incremental, lever. That figure is the algorithmic read volume; measured DRAM/SLC traffic is reported separately per §10.1.

### 6.2 The optimization doctrine (inherited, binding)

1. **Parity first** — no kernel lands without its bit-exact (integer) or tolerance-proven (float) gate.
2. **Native int8 MAC intrinsics for GEMM/GEMV; LLVM autovectorization for glue** (the 5×-slower hand-SIMD lesson).
3. **Register/cache blocking + offline pre-packing are mandatory** for any matrix-engine path (the un-blocked-SMMLA trap).
4. **Measured-faster wins, capability is not routing** — Apple autovec-vs-SDOT/SMMLA decided per shape by benchmark, recorded in the dispatch table.
5. **One lever at a time** with the 5-pass keep/revert loop and the NEGATIVE_EVIDENCE ledger (§10.2).

### 6.3 Per-arch SIMD dispatch catalog

One `int8_gemm` / `int8_gemv` / `int4_gemv` entry set, capability-detected once but **selected per fixed shape and regime from a measured dispatch table**. All tiers implement the same canonical integer algebra; AVX2 is not allowed a different answer. `fnlp robot backends` reports detected features, selected kernel id/tile, benchmark-table provenance, and the reason a wider tier lost:

| Tier | ISA gate | GEMM (prefill/batch) | GEMV (decode) | Notes |
|------|----------|----------------------|---------------|-------|
| **A1** | aarch64 `i8mm` actually exposed by the OS | SMMLA `vmmlaq_s32`, register/cache-tiled, packed K-panels | SMMLA or SDOT, whichever wins the shape | Candidate for any M4/M5/Arm host that advertises FEAT_I8MM; never infer it from marketing name |
| **A2** | aarch64 `dotprod` | blocked SDOT | SDOT `vdotq_s32` | Primary explicit-SIMD Apple candidate; runtime detect |
| **A3** | aarch64 autovec | LLVM-vectorized i32 MAC | same | *shipped-faster on M-series for some shapes in franken_ocr — first-class citizen, not fallback* |
| **X1a** | OS exposes `avx512f` + `avx512vnni`; 512-bit path wins sustained bench | `VPDPBUSD` zmm tiles + exact offset correction | same | Zen 4/5 Threadripper/EPYC and supporting Xeon; family-specific tiles |
| **X1b** | X1a features + `avx512vl`; 256-bit EVEX-VNNI path wins | VNNI ymm tiles + exact offset correction | same | Keeps VNNI semantics/register file while avoiding a losing 512-bit width on a given shape/host |
| **X2** | `avxvnni` | `_mm256_dpbusd_epi32` + exact offset correction | same | Supporting Intel/AMD clients; feature-detect, do not vendor-name route |
| **X3a** | `avx2` | exact low-7/high-bit `vpmaddubsw` decomposition (§6.5) | same | Primary Zen 3 candidate |
| **X3b** | `avx2` | exact sign-extend-to-i16 + `vpmaddwd` (§6.5) | same | Independent exact candidate; measurement chooses per shape |
| **S** | always | scalar i32 MAC | scalar | cross-compile floor, bit-exact oracle |

int4 storage unpacks to int8 in-register (no CPU int4 MAC exists) and feeds the same MAC paths — the win is bandwidth/footprint, exactly the property the loop doubles (§2.4).

**AVX-512 is a full optimization campaign, not one checkbox.**

- **Zen 4, Zen 5, and Intel are separate benchmark keys.** Zen 4 commonly executes 512-bit work through 256-bit datapaths; Zen 5 Threadripper 9000 advertises a full 512-bit datapath; Intel frequency/power behavior varies by generation. None of that alone chooses X1a. For every hot shape, compare zmm-VNNI, ymm-VNNI where available, AVX2, and scalar after warmup over a sustained forward—not a 5 µs microbench. Record clocks (where observable), joules/doc where available, p50/p95/p99, and thermal steady state. A narrower tier may be the default on a wider-capable CPU.
- **Width and semantics are orthogonal.** AVX-512-VNNI supplies the exact U8×S8→i32 primitive plus 32 registers and masks. AVX-512BW without VNNI is only an optional widened version of an exact AVX2-style decomposition; build it if an actual supported host and profile justify the verification surface. AVX512-BF16 is an optional f32-reference-prefill candidate, not part of the int8 correctness story.
- **Tails still exist.** K/N are favorable fixed dimensions, but batch/prefill row count M, sequence length T, vocabulary candidate count, and grammar work are dynamic. Masked loads/stores may remove scalar cleanup for M/N tails, while K padding must be converter-defined zero padding with digest coverage. Every masked-tail case has tests at 0,1,W−1,W,W+1 and page boundaries.
- **OS/firmware exposure is authoritative.** AVX-512 can be unavailable despite CPU family support (firmware/VM policy); dispatch uses the platform's reviewed runtime feature-detection surface, never a model-name table. `robot selftest` executes a tier only after positive feature detection — there is no portable, dependency-free way to run an unsupported instruction “guardedly” in-process, and attempting one risks exactly the crash the selftest exists to prevent. An optional child-process ISA probe may be added only after an approved OS surface can contain and report `SIGILL`/structured-exception failure without risking the parent. Forced-tier requests that are unsupported fail before dispatch rather than faulting.
- **AMX is out of v1.** It could be valuable for Sapphire Rapids+ prefill, but adds tile-state/OS enablement and a new packing/proof surface outside the primary Apple/AMD target. Reconsider only from a measured X1 bottleneck.

**Local tuning cannot turn a transient benchmark into a permanent machine fact.** Phase-6 `fnlp tune` starts with fixed-shape, bit-identical kernel choices and conservative thread caps only. Each promoted row is keyed by binary/kernel ABI, artifact recipe, CPU/ISA, OS/firmware exposure, topology/affinity, and a declared workload validity domain; batch size, mmap-vs-owned loading, NUMA placement, and page-cache-sensitive choices are not host-wide constants. Promotion requires repeated randomized A/B trials after warmup, thermal/load preflight, a confidence interval wholly beyond a practical minimum effect, and hysteresis. Noise, unsupported counters, a stale key, or disagreement between microkernel and representative end-to-end results retains the shipped default. `robot backends` explains the selected row and why any local profile was ignored.

**One canonical quantization algebra (cross-ISA bit identity is a theorem first, then a test).** Weights and logical activations are s8, zero-point 0. SDOT/SMMLA consume that representation directly. U8×S8 paths reinterpret `u = qx XOR 0x80`, accumulate `Σu·w`, then subtract the offline-checked `128·Σw`; this yields exactly `Σqx·w`. Canonical row sums are derived from the semantic logical weights; each native copy is protected by its physical section/file digest and checked against recomputed sums before dispatch. They are not mislabeled as independent semantic identity. Integer identity ends before dequantization; float scale application and int4 group summation have a separately fixed operation order.

### 6.4 Weight packing & the tiled GEMM (the build)

- Offline per-arch interleave (§5.1[4]); per-layer contiguity so `layer[i]`'s full weight set streams as one sequential range per loop pass (prefetch-friendly; NUMA-placeable §6.13).
- Tile geometry is specialized around K ∈ {3072, 6144, 10752} and fixed N values. Converter-defined zero padding is permitted only where a chosen K/N tile needs it; dynamic M/T/candidate tails remain real and are handled by proved masks or cleanup kernels.
- Register/cache blocking is selected from a bounded offline candidate set per `(ISA, shape, regime)`. Initial panel sizes come from L1/L2 capacity arithmetic, but only measured winners enter the dispatch table; there is no inherited “256 KiB is right everywhere” constant.
- The same micro-kernel serves prefill GEMM and **batched decode GEMM** (§6.7) — decode at batch M is a skinny GEMM (M×K·K×N), which is precisely where the tiled kernel beats M independent GEMVs.

### 6.5 AVX2 first-class proof (because the reference AMD box is Zen 3)

The `vpmaddubsw` hazard is **intra-instruction**: it saturates an adjacent-pair sum at i16, so no downstream accumulation cadence can restore lost bits. Raw U8×S8 pairs can reach 65,280 over the full i8 domain. Two exact AVX2 candidates are required:

1. **X3a low-7/high-bit decomposition.** For offset activation `u∈[0,255]`, form `lo=u&0x7f` and `hi=u>>7`. Compute `dot(lo,w)` with `vpmaddubsw`: each pair is bounded by `2·127·128=32,512`, so it cannot saturate. Compute `dot(hi,w)` the same way (pair bound 256), widen to i32, shift by 7, add, then apply `−128·Σw`. This reconstructs the canonical signed dot exactly while retaining byte-dot throughput.
2. **X3b widened signed route.** Sign-extend activation and weight bytes to i16 and use `vpmaddwd` into i32. It uses more unpack/half-lane work but has a short proof and is an independent oracle-quality SIMD path.

Measurement chooses X3a or X3b per shape; both must equal scalar/i64 on exhaustive small vectors, randomized property tests, all-extreme full K=10752 vectors, alternating signs, offset-correction extremes, and every tail length. Raw saturating `vpmaddubsw` is not a shippable “fast approximate” variant because the failure is data-dependent and silent. Zen 3 gains primarily from many-core batch GEMM, cache/NUMA placement, and exact prepacking—not from pretending it has VNNI.

### 6.6 The loop scheduler (`looprun.rs`)

- Straight-line plan: `for loop_idx in 0..2 { for layer in 0..22 { layer_forward(layer, kv[layer + loop_idx*22]) } hidden = final_rmsnorm(hidden); }` — no embedding re-injection or boundary projection. This observed rule is implemented once, truth-pack line-backed, and property-tested (including a named loop-boundary fixture).
- Per-`(loop, layer)` KV binding resolved at engine build; no hash-map lookups in the hot loop.
- **Loop-aware prefetch candidate:** the schedule knows loop-2 layer-0 follows loop-1 final norm, so a bounded prefetch distance is testable. Hardware prefetch/cache pollution may make explicit prefetch slower; it enters only after a counter-backed benchmark and may be rejected per CPU family.

### 6.7 Batched layer-major execution (`batchsched.rs`) — the structural throughput lever

The NLP workloads (§7) are corpus-shaped: thousands of short documents × one shared task prompt. Sequential batch-1 decode streams 3.7 GB per token per document — absurd waste when 64 documents could share each weight stream. The design:

- **Admission:** the batch daemon (§8.4) admits sequences only when the worst-case next-step KV/pages, activation rows, logits/candidate rows, grammar state, output buffering, and one safety margin fit both the engine's local ceiling and `EngineResources`' aggregate process ledger. `M` is the minimum of that certificate and a measured throughput cap—not a naked 16–128 guess. Per-sequence state is explicit and cancellation aborts/resolves its two-phase reservation and releases committed pages deterministically.
- **Asupersync team mapping:** one admitted `Cx::spawn_blocking` closure owns one `Cx::scoped_cpu` region for the whole request or bounded scheduling epoch. The coordinator forms the exact fixed team behind an entry gate, seals the only spawn phase, and only then releases children into a bounded command/reply loop; no worker performs fallible request work before the seal, and no layer or microkernel creates threads/tasks. The first safe-Rust design uses per-worker capacity-1 command/reply lanes, preallocated worker-owned output shards, and deterministic ordinal handoff/assembly at stage boundaries, so mutable aliases never cross workers; a disconnected per-worker reply lane identifies a panicked/exited child and lets the coordinator stop siblings rather than deadlocking on a fixed-count barrier. The assembly bytes and rendezvous cost are measured explicitly. A faster direct-write design may replace it only through a safe disjoint-range FrankenSuite abstraction—**not** a new scheduler-unsafe island. Every worker checkpoints its `CpuCx` before its first command and at tile/morsel boundaries; cancellation closes admission, sends stop, and joins the entire scope. Static range assignment is the deterministic fallback; any work-stealing candidate must preserve per-row reduction order and beat the fixed schedule in the ledger.
- **Step plan:** `for loop in 0..2 { for layer in 0..22 { GEMM over compatible rows } final_norm(rows) }`. Each physical layer streams **once per loop for all M rows**—two shared streams total, versus 2M independent streams. Idealized weight bytes per sequence-token approach `3.7 GB/M`, but attention, lm_head, packing, and incomplete rows prevent perfect amortization; the measured crossover is a deliverable, not “M=32 fixes it.”
- **Compatibility is operator-specific, not one whole-layer key.** Q/K/V/O and MLP linear work may batch rows with different context lengths, because the fixed K/N weight shapes match regardless of position; the attention substage receives explicit ragged sequence lengths/page tables and groups rows more narrowly only where its kernel requires it. Requiring one identical “attention shape” for a whole layer would fragment a heterogeneous corpus toward batch-1 execution and surrender exactly the weight-stream amortization batching exists for. The scheduler therefore builds a typed step DAG — `norm/quantize → shared linear group (keyed by recipe, numerics profile §1.1.1, loop, layer, op kind) → per-row or ragged attention group → shared output/MLP group` — preserving each row's dependencies and KV destination; compatibility keys are defined per node and belong to the model-checked scheduler spec. Prefill and decode rows mix only at operator boundaries proven semantically compatible; no kernel receives a padding or mask convention merely because two rows were convenient to place together. Long prefills are still chunked into bounded morsels so one 200K-token document cannot monopolize a step; decode latency has an explicit maximum-wait budget and can preempt further prefill admission between morsels.
- **Prefix cache (`kv.rs`):** prefill immutable task prefixes once and fork page references copy-on-write. The key is the exact prefix token ids plus a named projection of `ExecutionIdentity` (§4.3.1): artifact/recipe digest, tokenizer/template/prompt hashes, thinking/tool mode, RoPE/numerics/KV dtype, and kernel-semantic version. Default cache eligibility is restricted to shipped task/system prefixes—never arbitrary user document text—so cross-request reuse cannot leak private content. User-prefix caching is explicit opt-in and namespace-isolated. Correctness gate: forked prefix equals cold prefill. A byte-budgeted eviction policy starts as deterministic LRU; S3-FIFO becomes a candidate only after traces show scan pollution (§10.5).
- **Determinism:** under `strict-quantized-vN` (§1.1.1), batch composition must not change any sequence's tokens (row order in a GEMM changes no arithmetic per row; reduction orders are per-row). A determinism gate asserts batch-M output == batch-1 output token-exactly per sequence; any deviation is a bug, not a tolerance. `fast-vN` carries its own numeric/token-quality contract and may not reuse strict-profile cache entries. The mechanism, stated precisely: the integer paths (int8/int4 GEMM/GEMV, i32 accumulation) are exact regardless of blocking, hence batch-invariant by construction; the f32 paths (norms, softmax, attention accumulation, dequant-scale application) must keep **per-row reduction order identical between the M=1 and M>1 kernel variants** — a kernel-selection rule the gate enforces, not an accident we hope for.
- **Sequential fallback:** `--batch 1` (and the library default) preserves the simple latency path; the daemon is the opt-in throughput surface.

### 6.8 Attention kernels

- **Prefill:** an explicit 48:8 GQA adapter around frankentorch's dense f32 SDPA is acceptable as an L1/reference implementation; it must not materialize 6× KV in the production claim path. Build the native GQA kernel next. Post-parity candidates: online-softmax tiling after profile crossover (not a guessed fixed 8K), then int8 QKᵀ/scores·V behind an explicit runtime attention-backend/numerics selector with the proved higher-precision attention path resident and available. Do not call a selector a rollback unless the current artifact and loaded representation can actually execute the prior semantics.
- **Decode:** per step, per (loop, layer): q GEMV → RoPE → scores vs KV (8 KV heads × 128; block six query heads per KV head) → online softmax → weighted V sum → o GEMV. Logical addressing is `[loop-layer][head][position][128]`; the physical paged order below is selected by benchmark while preserving sequential position scans and 64-byte alignment.
- **KV pages:** a 16-token range (initial candidate; measured) is a **logical page group, not necessarily one indivisible allocation** — all 44 slots for that range total about 2.75 MiB bf16, far too much to clone on a small fork. Physical slabs are independently allocated and reference-counted by `(token range, loop-layer group, K|V, dtype)` or another measured bounded grouping, which makes small fork-tail copy-on-write, cancellation without retaining unrelated 44-slot storage, bounded allocator classes, selective layer scan/prefetch, low internal fragmentation, and exact per-slab admission accounting structural rather than afterthoughts. Candidate slab groupings — one loop-layer; 2/4/8 loop-layers; K and V together or separate; and the all-44-slots-in-one-page layout as a measured candidate, not the baseline — are compared for page-table overhead, TLB behavior, prefill writes, decode scans, fork fan-out, and cancellation. Sealed immutable pages plus small fork-tail slabs (down to one token) are weighed against explicit tail copy/recompute; admission prices the actual parent-fill state and fan-out before branching. Page tables, not a giant contiguous reservation, make cancellation and COW bounded.
- **KV int8 (runtime-gated):** payload falls from 176 KiB/token to 88 KiB, but scale metadata is counted, not hand-waved — separate f32 K/V scales per `(loop-layer, KV head, token)` add 2,816 bytes/token before alignment (f16 scales 1,408), plus padding and page-table overhead. “Approximately halves total KV” may be said only after including that overhead; enable only after long-context parity/task budgets and the added scale bandwidth are measured.

### 6.9 Memory, allocator, layout

- Owned weight buffer is the safety reference; `FNLP_MMAP=1` (CLI-mapped `FNLP_LOAD_MODE`; the library takes an explicit builder field) is the opt-in mapping island (trusted immutable artifacts; the franken_ocr posture). Mapping range/lifetime/immutability is proved locally. After R0/R1 measurements plus truncation/replacement, bit-rot, cancellation, and hostile-local-file tests, Phase 3 may promote `load_mode=auto` so content-addressed immutable installed artifacts use read-only mmap where the reviewed platform surface exists; locally converted or untrusted artifacts may stay owned. Prefetch advice and huge-page policy are separate measured experiments available only through a ratified safe FrankenSuite OS surface; without that surface they remain off rather than reaching through to `libc` or expanding the mmap island. Every experiment has the portable owned-buffer fallback and leaves the G3 “no foreign ML runtime” claim unchanged.
- Activation rails, per-step scratch, mask words, and scheduler metadata are reserved to the admitted batch envelope. KV pages are allocated only at admission/page boundaries from a pre-reserved pool; the inner token/layer loops perform no general allocator calls (allocation-count test). **Default per-sequence context cap is 8192, but admission is governed by an exact memory certificate, not one ambiguous number.** The budget decomposes into named terms: `--memory-budget-total` (maximum modeled process commitment; plain `--memory-budget` aliases it) · `--memory-reserve-os` (non-allocatable safety reserve) · fixed residency (mapped/owned active packing, tokenizer, immutable caches, runtime/pool) · the elastic engine budget (KV, activations, logits, grammar/source state, queues, output buffers) · optional replicated-weight/NUMA residency · an unmodeled/emergency reserve. `robot plan` prints every term, whether file-backed pages count as mapped versus resident, and the exact rejection reason; the admission invariant never compares KV alone against a “budget” that silently excludes a 4–10 GB model/packing residency. One bf16 sequence at 8192 needs about 1.38 GiB of KV; 64 such sequences would need about 88 GiB before activations, so the engine must queue/reject before promising that combination. Up to 262144 positions is an observed model limit, not a practicality promise; `robot plan --ctx --batch --quant` prints exact committed/peak bytes and the admission result without allocating.
- 64-byte alignment for all packed weights/activations; scales in SoA.
- Allocator: system allocator only in the release design. An alternative allocator requires a separately approved FrankenSuite surface and plan revision; benchmark fairness still records allocator identity.

### 6.10 lm_head strategies (`lmhead.rs`)

- **Generation:** full 3072→166144 GEMV (int8, recipe-staged) fused for greedy with the **complete ordered logit-processor stack** and argmax under a specified lowest-token-id tie break and explicit NaN/Inf policy (no materialized softmax over 166K). Top-k/top-p **still evaluate the full vocabulary**. With the pinned default `top_k=20`, a deterministic size-20 heap/selection may precede softmax and top-p filtering; when top-k is disabled, exact nucleus/top-p requires the full normalizer and probability rank order until cumulative mass crosses `p` — the baseline retains the bounded 166,144-entry f32 logit vector (664,576 bytes), computes max/sum in a fixed order, and uses a deterministic stable partial/full sort. No universal exact one-pass top-p over arbitrary logits is promised, and a one-pass streaming threshold is not exact and may not ship under that name.
- **Addressable seeded sampling:** at request admission, use the caller's seed or fill one `[u8; 32]` effective seed with exactly one pinned `Cx::random_bytes` call, then emit its 64-character lowercase-hex form in the result/receipt. The library type is `Seed256`; the CLI accepts either that 64-hex form or a decimal u64, which expands exactly as `SHA-256("fnlp-seed-u64-v1" || u64_be)`. Every random choice is `SHA-256("fnlp-sampler-v1" || length-framed effective_seed || stable_request_key || sample_index || decode_step || draw_index)`; no shared mutable RNG stream exists. `stable_request_key` is the canonical digest of the complete semantic request (input bytes or their authoritative content digest, task/recipe/prompt, artifact, options, numerics profile, and caller/job item id), never a caller-chosen id alone. Interpret the first 53 digest bits as one big-endian integer and map `u = n / 2^53`; nucleus ordering, ties, cumulative arithmetic, half-open selection intervals, and the final-rounding fallback are frozen by golden fixtures. Same seed + semantic request + named numerics profile is batch/reorder/resume invariant. `--seed` is legal only with sampling; an omitted seed is intentionally nondeterministic until the emitted effective seed is replayed.
- **Finite-candidate scoring names its probability space.** When a task needs a known candidate set, compute only those lm_head rows: C-row sliced GEMV instead of all 166,144. Single-token candidates need one projection. But the API and output schema distinguish **three mathematically different quantities**, and no scoring surface may blur them: (1) **`full_vocab_sequence_logprob`** — the sum of true model log-probabilities, which requires the full-vocabulary normalizer at every distinct hidden state even when only candidate rows are retained; (2) **`trie_local_conditional_probability`** — at each node, normalization over only the legal outgoing candidate edges, exact for the locally conditioned process and computable from sliced rows, but *not* the model's unconditional sequence probability; (3) **`sequence_score_softmax`** — a softmax over a named terminal sequence score (summed selected logits, mean, or terminal token), a task estimator rather than a model probability. Every response emits `score_space`, `normalization_scope`, the length/EOS rule, and whether full-vocabulary denominators were computed; the words “probability,” “captured mass,” and “confidence” are unavailable unless the corresponding quantity was actually computed (and, for confidence, calibrated per §7.8).
- **Exact continuation trie:** compile multi-token candidates into a token trie and evaluate each unique prefix state once; terminal/EOS is an explicit scored edge when one label prefixes another. “Exact” means exact **relative to the selected score space**: trie traversal cannot convert `trie_local_conditional_probability` or raw-logit sequence scores into `full_vocab_sequence_logprob` merely by visiting every candidate. This is dynamic programming over the *complete* candidate language, not beam search: no candidate may be pruned. Before allocation, the compiler estimates unique-node work **and actual KV fork-tail bytes** from trie breadth/depth, page fill, and the 44-slot geometry, then chooses among exact breadth/frontier batching, depth-first snapshot/restore with bounded tail state, or naïve per-candidate scoring. A compact canonical short-ID encoding is a separate quality/performance baseline, not assumed equivalent to semantic labels. The trie ships only when scores/rankings equal the naïve implementation under the same full-vocabulary or trie-conditional normalization, candidate order is irrelevant, admission is certified, and the measured reuse win exceeds traversal/KV cost. Little prefix sharing or excessive fork memory selects the naïve fallback.
- **Stencil sparse projection:** for constrained greedy or grammar-conditioned sampling, `ProjectLegal(rows)` evaluates **every** legal row and no illegal row when the compiled legal set is below a measured threshold. That is exact for the conditioned distribution because the omitted rows are impossible under the declared grammar. Dense states use `FullProjection(mask)`. No heuristic may omit a legal row.
- **Forced runs:** projection may be skipped only when the intersection of grammar/tokenizer legality, EOS/min-length/stop policy, banned-token policy, repetition/presence/frequency processing, logit bias, tool/thinking phase policy, and every other enabled processor leaves exactly one legal **token id independently of its unknown raw logit**, and no logprob/legal-mass/margin/audit telemetry was requested — “the grammar alone has one edge” is insufficient when a later processor could ban or alter that edge. Forced-run compilation stores a **proof witness** naming the processor-state facts that make the projection irrelevant; processor state that depends only on emitted ids (penalty windows) is still updated for every forced token, and any unsupported processor disables the optimization rather than being ignored (OQ-8/OQ-32). A uniquely determined byte suffix is **not** sufficient: multiple tokenizations of the same bytes lead to different hidden/KV states, so byte-level jump-forward, canonical retokenization, and token healing are excluded from this exact path. A maximal bounded run of uniquely forced token ids can be teacher-fed through a causal micro-prefill to update all 44 KV slots. The transformer work is not skipped. The micro-prefill path must match sequential feeding at every token/KV point under the designated numerics contract; otherwise the fallback is one-token feeding. If logprobs were requested, the required projection is still performed. OQ-19 measures whether exact-token runs occur often enough to justify retaining the optimization; rarity is an acceptable negative result.
- **Normalization authority:** candidate-conditional/trie-conditional normalization is cheap. A true full-vocabulary denominator—or legal/illegal mass or margin—requires the full lm_head at **that hidden state**. It can be batched across rows but cannot be cached across different hidden states or described as free. Every result and telemetry field names its normalization and reports unavailable quantities as `not_computed`.

### 6.11 Fusion catalog (bit-exact; each gated by the isomorphism proof)

| Fused unit | Replaces | Win |
|-----------|----------|-----|
| Gate/up projections share one quantized input; pairwise SiLU×up writes the canonical intermediate scratch | duplicate input quantization + separate activation/multiply buffers | one input quantization and one intermediate, while preserving the global down-proj activation-scale contract |
| RMSNorm output → one shared activation quantization feeding q/k/v (and separately gate/up at norm2) | repeated quantization per projection | norm scratch/max scan once, one quantized row reused |
| q/k GEMV epilogue → RoPE (rotate in-register before the KV write; RoPE applies to *projected* q/k, so this is the projection's epilogue, not a norm fusion) | extra pass over q/k | rotated q/k never round-trip through memory |
| residual add while accumulating next RMSNorm sum-of-squares, followed by the required normalization pass | standalone residual write + later norm read/reduction | removes one read; does not pretend RMSNorm is single-pass |
| lm_head GEMV → argmax (greedy) | full softmax + scan | argmax-only over 166,144 |
| grammar mask AND → sampler | separate mask pass | mask applied during logit scan |

### 6.12 Vectorized transcendentals — the measured exception

LLVM generally cannot turn scalar libm calls into the exact vector transcendental sequence we want, so a range-reduced minimax `exp`/sigmoid is a candidate for softmax/SiLU. It is **not known-fast here until profiled**, changes numerics, and cannot be described as SIMD≡scalar bit identity. It starts default-off, carries max-ULP/domain/monotonicity/NaN tests plus L1–L5 impact, and becomes default only per architecture/shape if the ledger wins. The reference libm path always remains available.

### 6.13 Many-core & NUMA scaling (Threadripper/EPYC + Apple P/E)

- **Two parallelism axes, never blindly mixed:** latency (one sequence: parallelize within the forward—row-blocks of each GEMM/GEMV across the admitted team) vs throughput (the §6.7 batch: parallelism lives inside the batched GEMMs; NEVER N concurrent independent forwards that create competing teams).
- **Decode at batch 1 stops scaling at bandwidth/coordination saturation:** a reproducible 1…available-width sweep directly selects the smallest team width within the confidence interval of peak throughput/latency. Physical-core/topology labels are used only when the safe resource probe established them; otherwise results say logical/effective width. A USL fit may summarize the curve and flag contention, but it never extrapolates a dispatch cap beyond measured points. No guessed “8–16” default enters code.
- **NUMA (multi-CCD/multi-socket TR/EPYC):** once a ratified safe FrankenSuite topology/placement surface exists, compare three explicit policies: bind workers+KV to one node and accept fewer cores; interleave shared weights; replicate read-only packed weights per node when the memory budget permits. “Local” without worker restriction causes remote reads, and “replicate” can double multi-GB footprint; admission includes the chosen placement. Per-node batch shards avoid cross-node writable state and merge only ordered results. Until that surface exists, `FNLP_NUMA` rejects non-portable modes rather than pretending a standard thread was pinned.
- **Apple P/E:** macOS offers **no hard thread-affinity API**, so "pin to P-cores" is not a portable guarantee. QoS is a measured optional experiment only through a ratified safe asupersync scheduling-policy surface; otherwise the portable no-QoS scoped team is the only route. `robot backends` reports requested versus observed effective placement. Per-shape autovec-vs-SDOT/SMMLA dispatch follows §6.2(4); the big-SLC effect on the double weight stream is measured, not assumed.

### 6.14 Build-time optimization (measured release recipes, not “free”)

Create a small matrix—thin vs fat LTO, codegen-units 1 vs a practical parallel value, PGO off/on—and measure clean build time, binary size, R1–R4 p50/p95/p99, and instruction-cache counters. Promote one reproducible profile per target only if its end-to-end gain clears the keep threshold; PGO training corpus ids/order and compiler commit are hashed. BOLT is Linux-only research after PGO and requires a separately replayed profile. `panic=abort` applies to shipped binaries only when the error/cancellation contract proves no unwinding dependency; an embedding application's final Cargo profile controls its library linkage. Portable target-feature baselines plus runtime dispatch are mandatory; never ship `target-cpu=native`.

## 7. The NLP task layer (the product)

> Everything before this section makes one model run fast. This section is why anyone installs the binary. Design mandate: **every task is (a) valid-by-construction (G8), (b) deterministic by default, (c) batch-first, (d) honest about quality** (task evals with named datasets, §9.6). The portfolio was generated and winnowed via the idea-wizard method: ~30 candidates scored on usefulness × exploitability-of-our-engine × honesty (can a 3B LLM actually do this well?) × implementation cost; the survivors below. POS/dependency/lemma pipelines were cut as non-goals (§1.2) — the honest answer there is "use a finite-state tagger."

### 7.0 The `Task` architecture

```rust
trait Task {
    type Request;  // serde types; CLI + library + NDJSON share them
    type Response;

    fn spec(&self) -> &'static TaskSpec;      // name, version, JSON Schemas (request/response), presets
    fn plan(&self, req: &Self::Request, ctx: &PlanContext)
        -> Result<TaskPlan, FnlpError>;       // prompt build + decode strategy + grammar + budget
    fn finalize(&self, req: &Self::Request, plan: &TaskPlan, raw: DecodeOutput,
                validator: &IndependentValidator)
        -> Result<Self::Response, FnlpError>; // G8: independent validation + grounded-offset checks
}
```

The old `parse(raw)` sketch was doubly wrong: `&Request`/`Result<Response>` are not valid references to associated types (they must be `&Self::Request`/`Self::Response`), and a finalizer without the request, plan, and source text cannot verify grounded fields or offsets. The built-in registry is a **closed `BuiltInTask` enum with static dispatch**; the associated-type trait deliberately does not support a heterogeneous `Vec<Box<dyn Task>>` (that would need a separate erasure layer we are not building). Public data-only recipes compile to `TaskIR`; they never become dynamically loaded Rust task implementations.

- **TaskPlan decode strategies:** `PrefillOnly { candidates }` (logit-sliced/trie-scored, §6.10), `ConstrainedJson { schema }`, `ConstrainedPattern { grammar }`, `FreeText { stops, budget }`, `Distribution { scale }` (§7.5). Tasks compose these; the engine doesn't know task semantics.
- **Semantic envelope vs telemetry envelope:** every response carries `schema_version`, the task spec version, the `ExecutionIdentity` projection (§4.3.1) including the **prompt-template hash** (prompt changes are versioned, diffable events — a quality regression must be attributable to weights, kernel, or prompt, so all three are hashed), thinking mode, deterministic token counts, calibration/policy identity, score space (§6.10), and result status. Timings, queue wait, selected tuning row, transient run id, page faults, host load, and energy observations live in a separate telemetry envelope; canonical byte replay (`--ordered` + canonical metadata) omits the telemetry envelope entirely.
- **Presets are data, not code** (`tasks/presets/*.json`): only repo-authored or provenance-cleared packs may ship/embed; every file carries origin/license metadata and a content hash. Users may supply `--preset-file`.
- **Bounded `TaskIR`, not a plugin system:** built-in task plans compile before model load into exact prompt-token segments, grammar/execution program, optional continuation trie, deterministic finite postconditions, resource bounds, and a stage dependency scope: `ItemLocal`, `PartitionReduce`, or `CorpusGlobal`. The scope controls cache/reuse authority—adding one item may preserve local map results but invalidates any reduce/global result whose child set changed. The runtime executes this IR; it never interprets arbitrary code. A later public `.fnlptask.json` recipe may expose only a frozen subset: typed prompt segments/placeholders, supported decode strategies, budgets, source constraints, finite postconditions, calibration references, and dependency scope that cannot be weakened by the caller. It may not execute code/tools, access the network, read undeclared files, embed Jinja/shell/Python/WASM, retry unconstrained, or add neural operators. Unknown keys forward-reject.
- **Prompt-segment ABI:** prompts preserve typed segments (`global policy`, `task instruction`, `document`, `answer scaffold`) rather than becoming an opaque string too early. That permits content-addressed common-prefix discovery without forcing an instructions-last layout. Corpus-major sharing is the default proven layout. Document-major `analyze` packs are eligible only per task after instructions-before vs instructions-after scorecards show no quality regression and cold-prefill equivalence passes; ineligible tasks run independently. No speculative “3.5×” arithmetic becomes a product claim before real token layouts and end-to-end measurements.
- **Typed trust boundary:** only trusted template code may inject role, thinking, or tool-control token ids. An `UntrustedDocument` segment is encoded through a constrained tokenizer path that excludes the complete `TemplateControlIds` registry (§2.5) — not merely tokens the tokenizer marks `special=true`, since the think/tool markers are `special=false` at pin — while preserving the document's decoded bytes (using ordinary/byte pieces); if exact byte preservation without a forbidden id is impossible, preflight rejects instead of silently weakening the boundary. Literal marker text remains ordinary untrusted content. This prevents control-token/role-boundary smuggling, **not semantic prompt injection**: instruction-shaped prose can still steer the model and is addressed by per-task matched clean/attack scorecards. Every output envelope marks fields derived from untrusted content; downstream agents must continue to treat them as data.

### 7.1 `fnlp extract` — schema-constrained structured extraction (flagship)

- **Contract:** user supplies the documented finite JSON-Schema subset (§7.3) + text. A successful result is schema-valid by construction and independently checked. String fields may opt into `"x-fnlp-source":"verbatim"`; then a successful value is a byte-exact source substring by construction. Normalized dates/amounts remain ordinary semantic fields. Repeated occurrences return all compatible intervals or a separately constrained occurrence choice; string membership alone never fabricates a unique offset.
- **Why flagship:** covers a broad set of bounded object/array extraction schemas and demonstrates G8. Unsupported JSON-Schema features reject by keyword; this is not “any schema.”
- Modes: single-shot; `--ndjson` batch; map-reduce for over-context docs (§7.10). Phase 5 may add explicit `--verify-semantic`: each non-verbatim field is rendered by a versioned, schema-aware claim template and checked with §7.6 faithfulness. This is a same-model, correlated second read—not an independent proof or correctness certificate. It defaults off until a locked task eval shows incremental error-catching value after false alarms and cost; results are `{entailed, contradicted, unsupported, not_checked}` with evidence and may feed a policy only after separate calibration. An eligible shared-document prefix may reduce the cost; a cold fallback remains correct and no “10% overhead” is promised before measurement.

### 7.2 `fnlp ner` + `fnlp resolve` — entities, offsets, canonicalization

- **`ner`:** typed spans over a configurable type set. Output uses half-open `{byte_start, byte_end, scalar_start, scalar_end}`; “scalar” means Unicode scalar-value index, not grapheme cluster or UTF-16 code unit. After OQ-17 passes, surface forms use the exact source-language constraint by default. Repeated occurrences remain `ambiguous` with candidate intervals unless a separately constrained occurrence selector resolves them; ordinary non-grounded recipe fields may still be `unanchored`, but are never silently relocated. Every accepted span satisfies `source[byte_start..byte_end] == text` on UTF-8 boundaries. `confidence` is a separately calibrated mention-correctness estimate—not a raw average of whichever tokens encoded the span.
- **`resolve`:** second stage over anchored NER output: lexical blocking → LLM pair scores only within blocks → deterministic graph clustering. Corpus results are independent of arrival/completion order: at flush, mentions sort by `(document_id, byte_start, type, surface)`, candidate pairs sort canonically, scores are frozen, and a named clustering rule runs once. Mention extraction and unchanged pair scores may be `ItemLocal` cache entries; final clustering is `CorpusGlobal`, bound to the complete corpus-snapshot digest, and reruns whenever that child set changes. Incremental heuristic clusters may be emitted only as explicitly provisional events; final ids never depend on scheduler timing and never pretend to be stable across different snapshots. Optional cross-snapshot `unchanged/new/retired/merge/split/ambiguous_match` lineage is Phase-7 work.
- This is the headline "what people used SpaCy for" surface, minus the parts a 3B LLM shouldn't do (§1.2).

### 7.3 The constrained-decoding engine (`grammar/`) — how G8 is real

- **Normative v1 schema subset:** root and nested `type` in `{object,array,string,number,integer,boolean,null}`; `enum`/`const` over JSON scalars; object `properties`, `required`, and **mandatory** `additionalProperties:false`; arrays with `items` and a finite effective `maxItems` (schema value or engine cap); finite string/output byte caps; and the namespaced string annotation `"x-fnlp-source":"verbatim"` after OQ-17. Reject `$ref`, recursion, `oneOf`/`anyOf`/`allOf`/`not`, `patternProperties`, arbitrary `additionalProperties`, `uniqueItems`, `contains`, semantic numeric/string keywords (`minimum`, `multipleOf`, `format`, general `pattern`), and `verbatim-normalized` until each has a valid-by-construction implementation. Canonical object-key order and JSON number spelling are part of the output schema contract. Unsupported keywords fail before model load. The v1 engine also bounds JSON Schema's mathematically unbounded numeric types: `integer` is a canonical signed/unsigned 64-bit JSON integer (with optional stricter task ranges); `number` is a finite IEEE-754 binary64 serialized by one canonical shortest-round-trip algorithm with NaN/Inf/overflow rejected; a maximum numeric lexeme length is enforced during grammar compilation and independent parsing; `-0` behavior and UTF-8-vs-escape emission are specified; and tasks needing arbitrary-precision decimals use a schema string plus a versioned decimal lexical constraint rather than silent rounding through f64. Every parser boundary in the product (schemas, manifests, metadata, TaskIR, NDJSON) rejects duplicate JSON object keys rather than accepting parser-dependent overwrite semantics.
- **Compile:** the accepted schema becomes a bounded typed-JSON automaton: ordered keys with optional/required transitions, enum tries, RFC-8259-compatible string escapes/UTF-8 and canonical number lexers. State/transition counts and estimated mask-cache bytes are computed with checked arithmetic and compared to per-request limits before allocation.
- **The hard part is tokenization alignment** (a token may cross several grammar states). The mask oracle consumes **detokenized byte transitions** through a vocab trie built when the approved tokenizer asset loads; it is cached by `(tokenizer_digest, schema_digest, grammar_version)`. Per-state masks are lazy and byte-budgeted, so an attacker cannot force `states×vocab` memory. That cache holds only the reusable schema/tokenizer product: document-specific substring/source automata, occurrence indexes, logical-unescape products, and any mask containing source-derived transitions are **request-owned and never enter the cross-request global cache** (an explicitly opted-in durable job may reuse them only inside its private namespace and storage policy), and cache accounting separates immutable schema masks from source-derived state so an eviction trace or `robot health` report cannot reveal document substrings or equality relationships. SentencePiece word-boundary and byte-fallback behavior belong to the detokenization transducer; raw piece text is never treated as emitted bytes.
- **Source-language product:** a bounded substring automaton over the original source bytes is intersected with the typed-JSON automaton and tokenizer detokenization transducer. The JSON lexer owns escaping while the source automaton sees logical unescaped UTF-8 bytes. Start-anywhere/finish/empty/min-length transitions, repeated occurrences, byte-fallback pieces, and offset recovery are specification—not implementation folklore. Preflight accounts for source-index bytes and rejects over budget. Unsatisfiable required grounded fields return a typed task no-result (nullable fields may emit `null` only if the schema permits it); there is no silent unconstrained fallback.
- **Execution compiler:** each product state emits one exact primitive: `ProjectLegal(all_legal_rows)`, `FeedForced(tokens)`, `CopyFromSource(state)`, or universal `FullProjection(mask)`. Thresholds select between equivalent paths by measured cost, never by dropping candidates. `fnlp schema check` compiles/resources-checks without model load; `schema sample` walks only the supported grammar for DX/fuzz reuse. Model-proposed `schema infer` is Phase-7 experimental because “compilable” is not “correct for the user's data.”
- **Runtime:** execute the compiled primitive; a dense state may still AND the 20.3 KiB legal-token mask into the full sampler scan. Greedy-under-mask is default. Thinking, if explicitly enabled, has its own token/time cap and stays outside the JSON region until the exact pinned close delimiter. Missing close delimiter, timeout, cancellation, unsatisfiable required source field, or output budget exhaustion returns a typed **no-result error**; it never emits a truncated object as successful and never retries unconstrained.
- **Diagnostics, not truth:** optional full-projection audits may report pre-mask argmax legality, legal mass, or best-legal minus best-illegal margin. Sparse projection cannot know illegal logits, so those fields are `not_computed`; candidate-conditional legal probabilities are labeled separately. These signals may reveal model/constraint tension but are **not a fabrication detector, correctness probability, or calibrated confidence** and cannot alone authorize acceptance/escalation.
- **Guarantees:** emitted successful bytes parse and validate through the `validation/` module, which shares no automaton states, transition tables, mask cache, or acceptance routine with the grammar compiler (only immutable declarative schema types), so “independently checked” is not circular; differential fuzzing feeds both compiler outputs and independently generated hostile byte strings to both paths to kill common-mode agree-on-the-same-bug designs. Grounded values pass an independent source-membership/offset verifier; EOS is legal only in accepting states; control/template tokens are illegal inside JSON; every reachable nonaccepting state has a path to acceptance within the configured remaining output bound or compilation rejects that request. Fuzzing covers random supported schemas, every token crossing class, byte-fallback/non-ASCII strings, JSON escaping, repeated substrings, empty-language/depth/length boundaries, sparse-vs-full projection equality, forced-vs-sequential KV equality, dead-state search, and cancellation at every emitted token. Separate Lexicon properties prove an untrusted segment cannot emit a control id and decodes to the original bytes; matched injection fixtures measure content steering without mislabeling that empirical result a firewall.

### 7.4 `fnlp classify` — zero-shot classification (logit-sliced)

- Labels + descriptions + text → single- or multi-label, with different probability semantics. **Single-label:** prefer opaque single-token verbalizers verified in the exact answer-scaffold context; a single-token candidate-conditional softmax is exact for that declared finite choice. Multi-token labels explicitly select one of §6.10's three score spaces — the default quality baseline is `full_vocab_sequence_logprob` unless a locked evaluation qualifies a cheaper estimator — with frozen length/prior correction. **Multi-label:** independent yes/no (or present/absent) verbalizers per label, calibrated and thresholded separately—never a softmax that forces labels to compete; multi-token verbalizers name their score space and calibrate it separately. Multi-token candidate sets compile to the exact continuation trie in §6.10 when its measured reuse wins; full-vocabulary teacher-forced and trie-conditional modes remain distinct. Label-query suffixes batch together and may fork a shared document/task prefix; the realized cost scales with unique trie states/label queries and is reported.
- Cost target: one shared document prefill plus batched label suffix/continuation scoring where the cache boundary permits. Compare accuracy, calibration, latency, and memory against a conventional classifier and the tested official `llama.cpp` baseline; do not market “one prefill” when multi-label suffixes add work.
- Presets: topic packs, intent packs, moderation/toxicity dimensions, spam, language-id. A non-LLM n-gram language detector is the preferred cheap route only after its model-data license/digest, language set, preprocessing, and locked accuracy/speed scorecard are recorded; “wire speed” is not a premeasurement claim.

### 7.5 `fnlp sentiment` — dimension scoring (the swiss_army_llama descendant)

- **Model:** focus-area presets (for example reviews, earnings calls, support tickets), each defining adjective dimensions, audience/context, and a `[-100,+100]` interpretation with 0=indeterminate. The project owner has authorized reuse of his own `swiss_army_llama` methodology/prompts/presets with attribution; every imported datum still gets an origin hash so later edits are auditable.
- **Mode A — `--mode distribution` (candidate default after quality proof):** one shared-prefix-cached prefill per `(doc, dimension)` and a closed, census-verified bucket vocabulary. The fast path computes only bucket rows and reports a **`single_step_candidate_conditional`** distribution (§6.10 score spaces); it must not report “captured mass,” because that requires the full 166144-row denominator. Bucket-token identity is census-verified **after the exact answer scaffold and leading whitespace**, never by tokenizing the label string in isolation. A full-vocabulary audit path computes true captured mass on the calibration/test sample and establishes whether the prompt reliably puts probability on the scale. Presets include an explicit `UNSURE/OFF_SCALE` bucket. Single-token opaque labels are preferred; multi-token alternatives use a frozen teacher-forced sequence-scoring/length-normalization recipe and require separate calibration. Report normalization mode, E[score], dispersion, entropy, calibration version, and abstention/off-scale decision.
- **Mode B — `--mode sampled --justify`:** independently implemented N-seed generations with grammar-locked score plus free-text justification and preregistered aggregation/interval recipe. It is inspired by the prior project's behavior, not copied code/data.
- **Quality gate (§9.6):** both modes are judged independently against held-out human labels/rankings and reliability targets. Cross-mode agreement is a diagnostic, not ground truth and not a reason to force two genuinely different estimators to coincide. Distribution mode becomes default only if it meets the task metric, calibration, full-vocab captured-mass, and throughput gates; otherwise sampled or abstaining mode remains default.

### 7.6 `fnlp judge` — rubric scoring, faithfulness, pairwise preference

- **Rubric mode:** score texts against provenance-cleared rubric presets; distribution is only a candidate default after the same held-out gates as sentiment.
- **Faithfulness mode:** claim (or answer) + source → `{entailed | contradicted | unsupported}` + evidence spans — the local RAG-verification loop (batchable over a whole retrieval log). NLI-style, classify-path cost.
- **Internal second-reader use:** `extract --verify-semantic` may reuse this exact versioned task, but its same-model correlation and per-field claim rendering remain visible in the receipt. Verification is a diagnostic/decision-policy input whose uplift must be measured per extraction domain, never a certificate attached merely because a second forward ran.
- **Pairwise mode:** A vs B under a criterion → preference + margin (from the two candidates' logprobs, order-debiased by running both orders and averaging — 2 prefills, still cheap). Feeds eval pipelines and rerank-by-judge.

### 7.7 `fnlp redact` + the rest of the portfolio (compact contracts)

- **`redact`:** union source-grounded/anchored NER spans with versioned deterministic rule automata, then resolve overlaps by a versioned recall-first interval policy. Rule patterns/locales and their precision/recall fixtures are data, not an unspecified regex oracle. Unanchored model guesses become warnings, never destructive offsets. Actions `mask|placeholder|pseudonymize`; pseudonyms are explicitly **not anonymization**.
- **Pseudonym contract:** implement RFC-2104/4231 HMAC-SHA-256 over the approved `sha2` primitive (RFC vectors mandatory), never `SHA256(secret || value)`. Input is domain/version plus length-framed namespace, entity type, and bytes under a named canonicalization policy. A caller supplies a high-entropy key of at least 32 bytes through an owner-only key file or inherited descriptor/stdin—not argv or telemetry—and supplies a nonsecret key id/version for rotation. Key-stdin and document-stdin are mutually exclusive. The semantic job key and receipt retain only a nonsecret key commitment `HMAC_K("fnlp-pseudonym-key-commit-v1")`, so resume with the wrong secret fails before emitting mixed pseudonyms; a caller label alone is not sufficient identity. Default output encodes 128 digest bits as lowercase hex with a type prefix. Collision handling is job-wide: before externally visible 128-bit output, the engine preflights or buffers the complete canonical-value set; any truncation collision between distinct values either fails closed or deterministically promotes the entire colliding class to the full digest. A truly streaming mode that cannot preflight uses full 256-bit pseudonyms from the start—never retroactively changes an already-emitted token. The secret is never logged, persisted in a receipt, or reused as the sampler seed.
- `--map-out` and ordinary `-o` use the §8.6 local-output transaction: owner-controlled parent, exclusive `create_new` staging, no symlink/reparse/device target, owner-only permissions/ACL, sync + same-directory activation, and no overwrite unless a separately explicit destructive policy is designed. The map never enters telemetry. `--verify` reruns the full detector union over the redacted output and returns a nonzero result plus leak report on residual findings; it is a useful clean-pass receipt, not a compliance certificate. Redaction remains defense-in-depth.
- **`summarize`:** length/style presets (`--words`, `--bullets`, `--tldr`), map-reduce over §7.10 for long docs, optional `--cited` (every bullet carries syntactically valid, byte-verified source spans — a **structural citation guarantee**, not proof the spans entail the bullet). The stronger word `grounded` is reserved for a separately qualified task version whose locked human factual-support evaluation and explicit semantic-support policy pass (§9.6); a same-model judge contributes diagnostics but cannot turn span membership into entailment.
- **`keyphrases`:** ranked phrases, constrained list output, exact-match anchoring, `--max N`.
- **`answer`:** context-limited QA: question + provided passages → answer + byte-valid span citations + abstain (`answerable: false`) calibrated per §7.8. The base contract is structural citation validity (spans exist in the supplied passages); `grounded` is claimable only by a task version whose locked evaluation measures semantic support of each material claim — the RAG companion (retrieval itself is frankensearch's job; we consume its output NDJSON shape).
- **`generate` / `chat`:** completion/chat with the native template, bounded thinking, seeded sampling, and streaming NDJSON. Tool declaration/rendering/parsing is compiled in only after OQ-10 has a line-backed XML/JSON parser contract and malformed-call fixture corpus; before that gate `--tools` returns a typed unsupported-surface error rather than shipping an unqualified parser. `fnlp` parses/emits tool-call data but **never executes tools**.
- **`textutil` (non-LLM, no-model-load):** `fnlp tokens` provides exact counts/ids for this tokenizer. `fnlp split` is a versioned conservative delimiter/newline heuristic that preserves exact byte spans and enforces byte+token budgets; its language coverage is measured. V1 `normalize` is deliberately narrow: CRLF/CR→LF plus explicitly requested ASCII horizontal-whitespace trim/collapse, while all other UTF-8 bytes remain unchanged. Each transform states whether it preserves bytes, scalar positions, or neither; where offsets must survive, an original↔normalized coordinate map is part of the contract. Source-grounded NER/extraction never normalizes away from the original document unless such a lossless map is in the task plan and independently verified — a span that cannot map back to exact original UTF-8 boundaries is `unanchored` or a no-result, never approximately relocated. NFC/NFKC/case-folding may ship only with generated Unicode tables whose Unicode version, source license, generator digest, and conformance suite are pinned—never under a vague “Unicode normalize” label. The optional n-gram language detector likewise carries versioned/licensed model data and locked accuracy/speed evidence.

### 7.8 Confidence & calibration (cross-cutting)

Raw LLM logprobs are not confidence claims. Each calibrated task has disjoint development, calibration, and locked test ids. Temperature/isotonic parameters fit only calibration data; reliability/ECE/Brier/selective-risk is reported only on the locked test. Conformal abstention/prediction sets are used only where the exchangeability/unit-of-analysis assumptions are written and checked; coverage is stated for the named dataset/population and finite sample, never universally. Recipe, prompt, label set, thinking/numerics mode, calibration digest, and validity date key the artifact. Distribution shift invalidates the coverage claim and falls back to raw scores labeled `uncalibrated` or conservative abstention—never silent extrapolation.

**Selective automation is static and user-owned first.** After a task has a valid calibration artifact, a versioned `DecisionPolicy` may map task-valid signals to `{accept, explicit thinking retry, explicit N-seed aggregate, abstain, review_spill}` under a declared loss table. The initial policy is an offline-fit deterministic table; all retries/discards count in cost and every accepted result records the authorizing signals/policy. Constraint diagnostics from §7.3 are advisory unless independently calibrated on the same task. Corrections imported into an explicitly named local suite may support a later `eval/calibrate/policy fit`; there is no hidden online learning, prompt mutation, cloud escalation, or automatic incorporation into project scorecards. Ordinary task output/abstention is the immediate fallback.

Review-spill corrections are **selection-biased toward cases the current policy already considered hard**; they cannot estimate error among confidently accepted production results or silently extend a qualification's validity. Only an independently sampled audit with known inclusion probabilities and human-authorized grades (AA-A1) may update that accepted-population evidence. Qualification/policy artifacts name population assumptions, validity/expiry conditions, and shift indicators; invalidation yields `uncalibrated`, increased review/abstention, or a new qualification—not hidden online refitting.

### 7.9 Thinking-mode policy

Conservative pre-evaluation default is **off for every structured/batch task**, including judge and answer; `generate/chat` honors the model-template default. Each task exposes a bounded explicit override. Thinking tokens never enter the task JSON, prompt caches are keyed by mode, and a missing close delimiter fails as described in §7.3. Phase 5 may promote thinking per task only when the locked eval's accuracy/selective-risk gain justifies p95 latency, energy, and output-token cost.

### 7.10 Long-document map-reduce (`mapreduce.rs`)

Shared spine for summarize/extract/score-over-long-docs: deterministic token-budgeted chunking → batched map → task-specific deterministic reduce, with every output linked to chunk ids/byte ranges. Because 44-deep KV makes even 32K expensive and full attention is quadratic in prefill, map-reduce is a primary operating mode, not an edge case hidden behind the reported 256K maximum. Conflict/dedup rules, score weights, reduce fan-in, and lossy-summary warnings are versioned; hierarchical reduction never claims exact equivalence to single-context inference.

### 8.3 Robot / NDJSON contract

Versioned NDJSON events (`schema_version` on every line): `run_start`, `stage`, `doc` (per-document success), `doc_error` (typed per-document failure), `token` (streaming generate), `flush` (numbered corpus/cluster boundary), `run_complete`, `run_error`. Every nonempty input line receives a checked monotonic `request_seq` before parsing, and every event or parse error caused by that line echoes it; a reused caller id can therefore never make completion-order output ambiguous, and sequence overflow cleanly ends admission. `robot schema` self-describes; a frozen-schema contract test guards it. Semantic replay is deterministic only under the named greedy-or-seeded sampling and numerics profile. Byte-identical replay additionally requires `--ordered`, the same canonical metadata profile, and omission of volatile run ids/timings/host counters. Canonical JSON recursively orders object keys by UTF-8 bytes, uses the pinned serializer's number/string escaping rules, and rejects non-finite floats rather than relying on map iteration order.

### 8.4 The batch daemon (`fnlp batch`)

Long-running process; NDJSON requests on stdin (`{id, text, task_args?}`), bounded by line/document/token/schema/output sizes before admission. Default emits completion-order results with caller id plus engine-assigned `request_seq`; canonical byte replay requires `--ordered`, a declared maximum reorder window, and telemetry-free output. Backpressure pauses reads; duplicate caller ids are rejected within a numbered epoch, whose seen-id set is capped and resets only after a drained `flush`; one malformed document emits one `doc_error` with its sequence position without corrupting framing. EOF requests a graceful drain. First SIGINT closes admission and requests cooperative cancellation; a second shortens the CLI grace policy but is never described as safely preempting Rust/OS threads—the process emits no success receipt and does not reuse an in-process buffer before the compute completion latch. `resolve` collects mentions and emits deterministic final clusters only on a numbered flush/EOF transaction. Weights load once. The daemon's long-lived internals — admission feeder, scheduler pump, output writer, and (when jobs are enabled) journal/spool writers — are **supervision candidates**: where the OQ-35 census ratifies the pinned supervision/`GenServer` surfaces, they run as named children of one supervised tree with explicit restart policy and deterministic start/stop order, the command/reply lanes' reply-obligation semantics map onto `call` (a reply is owed and tracked) versus `cast` (explicit overflow policy = our bounded backpressure), and any AA-R1 resident experiment would sit under the same tree with registry name-leases rather than an ambient service locator. Absent ratification, the §3.3 explicit region tree with hand-rolled restart-on-error remains the proven fallback; either way, restart behavior is part of the model-checked lifecycle, never an incidental loop hidden inside a worker.

**Durable jobs are a separate opt-in contract, not magic attached to an arbitrary pipe.** `fnlp job start` canonicalizes a replayable manifest and freezes a corpus-snapshot **commitment** plus semantic execution key over ordered input ids/bytes/normalization, artifact and packing, tokenizer/template/prompt/grammar/TaskIR including dependency scopes, task args, calibration/policy, numerics/KV/thinking/sampling **including the effective seed and addressable-sampler version**, output schema, and engine semantic version (an `ExecutionIdentity` projection, §4.3.1). Private content is not identified by raw SHA-256 anywhere that leaves owner-only job state: each owned job generates a random 256-bit job secret and computes domain-separated HMAC-SHA-256 commitments (RFC-vector-tested over the approved `sha2` primitive, like §7.7's pseudonyms) for input bytes, normalized bytes, and result bytes, because raw digests of low-entropy documents invite dictionary and cross-job equality attacks. The secret never enters telemetry, public receipts, or filenames; public receipts expose a random job id, the execution identity, item counts, and a commitment root. Trusted public artifacts, repo-shipped prompts, and release assets keep ordinary SHA-256 — they are not secrets. Item ids must be unique across the complete frozen snapshot, proven before execution with a bounded external-sort/index when the corpus exceeds memory (the live `batch` daemon's windowed duplicate rejection is a different, weaker contract). Cache entries name their stage and scope: `ItemLocal` may reuse an exact item key; `PartitionReduce` must rerun its deterministic reduce when the complete child-set digest changes; `CorpusGlobal` authority is valid only for the exact snapshot. fsqlite records `pending → admitted → running → result_committed → materialized`, but a database transaction cannot atomically commit an external spool append by itself, so the normative protocol is **spool-first, journal-second**: (1) encode one canonical framed result with item id, execution identity, length, and keyed result commitment; (2) append the frame to the same-job result spool; (3) flush/sync the spool per the declared durability mode; (4) commit `(spool_generation, offset, length, commitment)` plus `result_committed` in fsqlite; (5) only then acknowledge durable completion. Recovery scans only to the last journal-authorized frame, independently validates framing and commitments, truncates or quarantines any uncommitted/torn tail, and never trusts a valid-looking spool record absent its committed journal pointer. Materialization derives only from committed pointers and is itself staged, synced, and atomically published; input spooling follows the corresponding spool-first/journal-second order, and directory-entry durability/replacement semantics are documented per platform rather than waved through as “fsync makes it atomic.” Interrupted pre-commit states are retryable. `resume` refuses any key mismatch with a field-level diff; `verify` checks journal/spool/materialization consistency; `materialize --ordered` writes one canonical record per item.

The authority boundary is explicit: when the job owns a checksummed spool and output materialization, it can promise one canonical committed record per item. Raw stdout to an arbitrary consumer can promise only stable ids and documented at-least-once replay. Default journal tables contain ids, digests, state, attempts, metrics, and errors—**not input text or output bytes**—so resume requires the original manifest. `--spool-input`, `--spool-results`, and incremental result caching are explicit privacy/storage choices with owner-only permissions, byte/retention budgets, and inspect/purge commands. Kill/disk-full/corrupt-tail injection at every transition must show uninterrupted ≡ resumed semantic output in ordered deterministic mode; where the OQ-35 census ratifies them, these campaigns run as seed-bound lab chaos scenarios (deterministic cancellation/delay/budget-exhaustion injection plus reusable crash/restart scenario definitions) so a failing interleaving replays from its seed and crashpack instead of being a one-off CI ghost.

Phase-7 acceptance sampling, if AA-A1 survives review, operates only on a frozen, verified owned job population. `audit plan` deterministically selects ids from preregistered strata using SHA-256 ranking over `(job_digest, audit_seed, stratum, item_id)`; it does not materialize text/results unless the operator explicitly requests a protected review pack. `audit grade` accepts human-authorized labels and reports only the finite-population/stratified claim its frozen design supports. Model self-grading cannot authorize acceptance. The receipt binds the population, strata, estimator, risk thresholds, sample ids, grader provenance, and missing/invalid grades. Post-hoc stratum or threshold changes create a new audit, never rewrite the old claim.

### 8.5 Exit codes & env

`0` ok · `1` generic · `2` usage · `3` model not found · `4` input decode/parse error · `5` budget/timeout · `6` cancelled · `7` artifact integrity/format/version mismatch · `8` schema/recipe compile error · `9` admission/resource limit · `10` structured task no-result. Calibrated model abstention is a **successful** typed result (`0` with `status:"abstained"`); code `10` is for an execution that cannot produce a valid task result at all — an unsatisfiable required source field, a missing mandatory thinking close delimiter — not for ordinary abstention. Exit codes are the policy boundary where the foundation's four-valued `Outcome` collapses (§3.3): budget/deadline exhaustion maps to `5`, cooperative cancellation to `6` with the structured cancel kind (user, timeout, shutdown, parent) preserved in the diagnostic payload, and a panic is never laundered into a per-document error — it is a supervised failure that produces `run_error` plus heavier evidence. The CLI snapshots `FNLP_*` once into `NlpEngineBuilder`; the library never reads environment variables behind its caller's back. Immutable capability detection and the one-time resource broker may be process-global. Runtime preset, compute/blocking widths, and aggregate process memory ceiling are first-install resource-host fields; a conflicting later builder fails typed. Batch/context/numerics/NUMA/mmap and lower local memory ceilings remain explicit engine configuration. Forced ISA runs selftest first and fails on absent capability.

## 9. Verification & conformance methodology

Apply `/porting-to-rust` (spec-first), `/testing-conformance-harnesses`, `/testing-golden-artifacts`, `/running-the-gauntlet-on-your-rust-port`. **Parity gate FIRST, perf second.**

### 9.1 The reference oracle

- **Primary behavioral oracle:** a Phase−1-selected, fully pinned Python/Transformers/PyTorch/CPU-kernel environment closure running the exact remote-code revision with CPU placement forced, inference mode, and `attn_implementation="eager"` — the version fields serialized in model files are candidates, not the authority (§2.2). The closure records Python, Transformers, PyTorch, BLAS/oneDNN, compiler/build tags, CPU features, thread counts, deterministic-algorithm settings, and every kernel-affecting environment variable. **A text-only dense model, so a CPU oracle is expected to run as-is** (unlike franken_ocr's CUDA-oriented `infer()`); Phase −1 proves it and audits the oracle's own nondeterminism floor with at least five independently launched processes at each of at least two preregistered thread counts. If any metric varies, a preregistered additional-repetition/convergence rule bounds its confidence interval and identifies the exact stable prefix; no tolerance distribution is inferred from two observations, and no unstable suffix is promoted as an exact golden.
- **Numerics matrix:** fixtures are generated for both `hf-bf16-eager` and `diagnostic-f32` (§1.1.1); a separately recorded `hf-bf16-sdpa` run measures backend variance but may not redefine eager source semantics. Every fixture names its dtype and attention backend.
- **Trace instrumentation (the 44-execution capture problem):** standard `output_hidden_states=True` is insufficient for the L2 ladder because the pinned source overwrites `last_loop_all_hidden_states` at the end of each loop and returns only the final loop's collection **[OBSERVED@pin]**. `scripts/gen_reference_fixtures.py` therefore installs side-effect-free forward hooks (or a minimal, separately hashed trace-only patch) that record loop index and physical layer index; pre-layer, post-layer, both post-loop final norms, pre-lm-head, and logits; prefill and one-token-append KV tensors for all 44 slots; and prove traced ≡ untraced logits/tokens. The instrumentation, source spans, commands, serialization format, and no-perturbation receipt join the truth pack (OQ-30).
- **Secondary differential:** a Phase −1 tested official `llama.cpp` revision at or after `b77d646…` (nearest-format tokens/perf cross-check). The authors' `nanbeige42` fork is a historical lineage check rather than an independent vote. GPL-3.0 `rlx-nanbeige` may be run out-of-tree as an opportunistic black-box differential; no code or dependency crosses into this repository.
- **In-repo scalar specification engine (dev/test only):** deliberately simple logical f32 tensors, direct 22×2 loops, explicit 44-slot KV, dense reference GQA expansion, and stable scalar reduction order. It is not production fallback code and shares no packed/SIMD implementation with the optimized engine. HF remains the semantic authority; this readable executable spec localizes divergences and prevents two optimized paths from merely agreeing on the same bug.
- `scripts/gen_reference_fixtures.py`: profile-tagged per-execution traces (post-embed; per (loop, layer); both post-loop norms; pre-lm_head; logits), prefill→decode KV-append traces, greedy token streams for the golden prompt corpus, template renderings across the mode matrix, tokenizer id sequences over the multilingual/code/special corpus, and sampled streams at fixed seeds where reproducible. Raw floating-point fixture digests are never presented as portable cross-host proof (§9.2).

### 9.2 Parity ladder (gates L0–L5)

| Gate | Granularity | Tolerance |
|------|-------------|-----------|
| **L0 tokenizer + template** | token ids; rendered prompts (all thinking/tools modes) | **exact** |
| **L1 per-op** | each kernel vs the matching profile's scalar/oracle implementation (§1.1.1) | integer exact; float max-abs/max-rel/ULP/cosine plus NaN/Inf/signed-zero checks, thresholds derived separately per op for `hf-bf16-eager`, `diagnostic-f32`, and quantized profiles from the measured oracle floor—never cosine alone |
| **L2 per execution** | all 44 post-layer outputs, **both post-loop final-RMSNorm states**, and named pre/post attention/MLP bisect points (trace-hook fixtures, §9.1) | profile-specific metric vector; loop-1 post-norm ≡ captured loop-2 input is a named equality fixture under the same traced execution |
| **L3 logits** | f32 exported pre-processor logits | `hf-bf16-eager`: measured oracle tolerance + exact argmax over the stable set; `diagnostic-f32`: f32-oracle tolerance; same-recipe optimized backend within its exact/tolerance contract; quantized: preregistered error distributions and argmax-agreement rates, never a universal exactness fiction |
| **L4 tokens** | greedy decoded stream after the complete processor stack | exact over the oracle-reproducible prefix for `hf-bf16-eager`; `diagnostic-f32` flips recorded as named divergence fixtures, not failures; optimized-vs-scalar exact for one fixed recipe/profile; quantized: separately frozen deterministic self-streams plus measured HF-agreement metrics |
| **L5 task outputs** | end-to-end task JSON on the golden corpus | exact where deterministic (constrained greedy); score drift within documented band |

Determinism is scoped by the §4.3.1 compatibility key `(artifact, logical recipe, packing set, numerics profile, backend-semantic version, compiler, CPU feature class, sampler version)`: semantic greedy outputs are exact under one named profile; seeded sampling follows §6.10; canonical byte replay additionally fixes ordering, canonical JSON metadata, and excludes timings/run ids. Batch-M≡batch-1 and prefix-fork≡cold are exact only for kernels that preserve the canonical reduction order; approximate numerics modes carry separately named tolerance/quality contracts and cannot silently become the deterministic default. Cross-machine floating-point byte identity is **not** implied. A later `portable-repro-v1` profile may use a repository-owned correctly specified math/reduction layer only after cross-ISA fixtures prove its exact contract and the performance cost is published; until then receipts name the ISA/compiler/numerics validity domain.

### 9.3 Differential / metamorphic / golden / fuzz

- **Differential:** ours vs oracle(s) per-op and end-to-end; ours-int8/int4 vs ours-f32; every integer SIMD tier vs canonical scalar/i64; every packed layout vs logical weights.
- **True metamorphic invariants:** batch composition and prefix fork equivalence; Generic→arch packing preserves logical tensors; ordered NDJSON scheduling preserves per-id semantic results; grammar success validates independently; grounded values occur in source under the named byte contract; untrusted-segment token ids exclude every control id while decoding to the same document bytes; sparse legal-row projection equals full projection after masking; forced causal micro-prefill equals sequential feeding; every continuation-trie execution mode equals naïve candidate scores; killed-and-resumed owned jobs equal uninterrupted jobs; an item-only snapshot change preserves exact unaffected `ItemLocal` entries but invalidates/recomputes every changed `PartitionReduce`/`CorpusGlobal` authority; anchored NER offsets survive deterministic coordinate conversion; artifact splitting/reassembly preserves the whole digest. Label-order sensitivity, content-injection response, negation response, prompt-segment order, and document-concatenation effects are **quality probes**, not invariants—the model is allowed to be context/order sensitive, so those results are reported rather than asserted mathematically.
- **Golden** (`/testing-golden-artifacts`): frozen task outputs (exact for constrained greedy; scrubbed for timings/ids), CLI help, robot schema — `UPDATE_GOLDENS=1` with mandatory diff review.
- **Fuzz** (`/testing-fuzzing`): tokenizer (arbitrary input → encode/decode never panic; the correctness bar is **parity with the reference tokenizer's own canonical behavior** — SP normalization means `decode(encode(x)) == x` is *not* a general property, so byte-losslessness is asserted only on paths where the reference itself is lossless, e.g. byte-fallback; the separately declared untrusted-segment path must byte-round-trip or reject and must never emit a control id), schema/TaskIR compiler (arbitrary input → compile-or-clean-error, never dead/unbounded or executable), grammar/source products (random walks parse; grounded fields independently occur; adversarial Unicode/escapes/repetition/empty languages), `.fnlpq` reader (malformed headers rejected loudly), NDJSON daemon (malformed lines → doc_error, stream survives), job journal (kill/disk-full/torn-tail recovery), and audit sampling/math (population/order invariance, golden exact enumeration on small finite populations, missing-grade fail-closed behavior).
- **Deterministic-lab vehicle:** the async portions of the scheduler, daemon, jobs, and pull programs run under the pinned foundation's deterministic lab wherever the OQ-35 census ratifies it — same seed, same execution; oracles for quiescence, obligation leaks, loser drain, and the cancellation protocol evaluated on every run; obligation-based futurelock detection upgrading the `many_docs_without_deadlock` watchdog from a timeout heuristic to a held-obligation proof; seed-bound chaos (cancellation/delay/budget-exhaustion/wakeup storms) replacing hand-rolled hostile interleavings for async state; and failing runs auto-attaching a crashpack (stable fingerprint + replay command) that enters the evidence ledger. Per §3.3's capacity certificate, the lab does not enumerate native `scoped_cpu` OS-thread interleavings — the repository's bounded team-state model and native stress/replay retain that half of the proof.
- **Structured-concurrency proof split:** pinned asupersync LabRuntime scenarios run to `run_until_quiescent_with_report()` and assert region/task/obligation/cleanup invariants, cancellation propagation, loser drain, and futurelock freedom. Native `scoped_cpu` children are OS threads outside Lab's schedule enumeration, so those reports are never mislabeled a proof of every CPU-team interleaving; a small repository-owned abstract team automaton exhausts bounded formation/seal/command/cancel/panic/join states, and native hostile stress/replay validates that abstraction's seam against the real implementation.
- **Model-gated e2e:** ordinary CI reports an explicit `SKIPPED_NO_MODEL` result rather than a counterfeit pass. Release certification requires the armed job and records artifact digest + proof that the native path ran (all fallback locations pointed at `/nonexistent`).

### 9.4 Ledgers & scorecard

`docs/DISCREPANCIES.md` (every accepted divergence: reference behavior, ours, measured impact, validity envelope, the **real** rollback authority—backend/profile selector or prior immutable-artifact activation—and review date) · `docs/NEGATIVE_EVIDENCE.md` + `docs/PERF_LEDGER.md` (artifact-graph format: claim_id, evidence, fixture hashes, CPU feature string, exact command+env, disposition) · `docs/FEATURE_PARITY.md` (FeatureUniverse/SurfaceMatrix: every subcommand, robot event, exit code, env var, task, preset — `present|partial|missing|n/a`; partial never rounds up) — all inherited formats from the shipped franken_ocr practice.

### 9.5 The gauntlet — three-pillar release certification

Three independent pillars: **(a) Performance** (per-stage/per-regime distributions and fair baselines), **(b) Conformance** (L0–L5, property/model-check/fuzz, task evals), and **(c) Surface parity** (FeatureUniverse). Load-bearing deterministic claims use the right authority: checked arithmetic/formal bounds for accumulators and capacity; exhaustive/property differential tests for SIMD; for scheduler/cancellation, deterministic-lab runs with oracle suites, DPOR-style schedule exploration, and seed-bound chaos over the async state machine (crashpacks and, where useful, exported TLA+ behaviors as the model-checking artifact) combined with the repository's bounded native team-state model and hostile stress/replay for the `scoped_cpu` OS-thread half (§3.3, §9.3); independent validation + grammar fuzz for JSON; exact fixtures for batch/prefix determinism. Statistical task metrics use preregistered point estimates and confidence intervals on locked data. There is no dimensionally meaningless “Beta-posterior × conformal” aggregate and no statistical process standing in for a proof. Release requires every hard gate green and ≥2 consecutive clean full runs after the last load-bearing change; the **implementation gauntlet** targets ≥10 adversarial convergence rounds, distinct from the ≥4 independent plan-review rounds required before Beads conversion.

### 9.6 Task-quality evaluation (the layer franken_ocr didn't need)

Kernel parity proves faithful execution, not useful tasks. Every dataset first enters `docs/eval/DATASETS.md` with immutable source, exact license text/terms, allowed use/redistribution, preprocessing digest, unit of analysis, development/calibration/test ids, and known contamination/leakage risks. A script may download only when the terms permit automated access; otherwise the harness accepts a user-supplied file and verifies its digest. “Fetch by hash” is not a substitute for permission. Only repo-authored fixtures or explicitly redistributable data are committed.

- `ner`: candidate corpora include WNUT-17 and Few-NERD **only after their exact upstream licenses are archived**, plus a repo-authored modern-web/CJK set. CoNLL/OntoNotes/Reuters/LDC-class candidates remain user-supplied when terms require it. Report span-exact/type-relaxed F1, anchoring status, and performance by language/type.
- `resolve`: blocking recall before LLM scoring; pairwise precision/recall/F1; B³/CEAF-class cluster metrics where licensed labels permit; overmerge/undermerge rates; singleton behavior; deterministic snapshot-id stability; runtime versus candidate-pair count. A good clustering score cannot hide blocking false negatives.
- `extract`: schema-diverse fixture corpus (field-F1, 100% validity by construction — validity is asserted, accuracy measured).
- `classify`: candidate sentiment/topic/intent corpora (SST-2/AG-News/Banking77-class) after the same license gate, plus owned multilingual smoke; accuracy/macro-F1/Brier/ECE/selective risk.
- `sentiment`: disjoint calibration/test splits with human labels/rankings, rank correlation/MAE/reliability/selective risk, full-vocab captured-mass audit, and cross-mode agreement as a diagnostic. Directional negation probes remain sanity reports, not universal linguistic laws.
- `judge`-faithfulness: licensed/owned entailment labels; `answer`: answerability, answer correctness, **citation validity and citation support as separate metrics**, and selective risk; `summarize`: length/coverage, citation validity, citation-support precision/recall, and a human-annotated claim-level factuality subset (any external LLM judge is disclosed and never the sole gate); `redact`: synthetic and licensed realistic PII with recall-first reporting, precision, unresolved-anchor rate, **and per-detector rule metrics** (recall/precision per detector, overlap policy, Unicode obfuscation, checksum/Luhn behavior where applicable, residual-leak verification).
- `keyphrases`: source-anchoring rate, exact/partial-match P@K and R@K where references exist, duplicate/stem variants, diversity, and blinded human usefulness on owned data.
- tool-call parsing (OQ-10-gated): exact accepted-call ASTs, malformed XML/JSON, duplicate arguments, nested/multiline values, adjacent calls, mixed natural language, missing delimiters, and the parser recovery policy for both pinned formats. Parser success is a separate metric from tool-selection quality.
- `tokens`/`split`/`normalize`: exact reference-tokenizer parity, byte/scalar coordinate properties, Unicode-version goldens, adversarial length bounds, deterministic chunk coverage/overlap.
- public `TaskIR` recipes (when enabled): built-in equivalence, resource-bound enforcement, unknown-key rejection, trust-segment preservation, and no-code/no-network properties.
- Every document-consuming task includes matched clean/adversarial-content fixtures across role-marker text, refusal steering, false-negative steering, value steering, and tool-call bait. The structural control-id property is an invariant; **content-injection resistance is only an empirical per-task attack-success metric** and may block a consequential preset without supporting a universal “prompt-injection safe” claim.
- Every scorecard states: model recipe id, thinking mode, prompt hash, dataset version. Regressions gate releases at the same rank as parity.

Assay is also a user surface, but a user scorecard is never promoted into a universal project claim. `fnlp eval` consumes versioned task-shaped NDJSON and emits the same digest-bound metrics; `calibrate` requires a disjoint calibration split; `qualify` performs paired candidate-vs-active replay under caller-declared gates and writes a host/dataset/config-scoped receipt. Dataset overlap/duplicate detection, tiny-sample `INSUFFICIENT_DATA`, stale-digest substitution, and activation rollback are tested. `models activate --require-qualification` accepts only an exact matching receipt and leaves the previous content-addressed configuration available; installation and activation are distinct. User corrections enter only an explicitly named local suite.

### 9.7 Claims, behavior, receipts, and structural-cost registries

The sibling plans' strongest lesson is to make proof state machine-checkable rather than bury it in prose:

- **`docs/CLAIMS.json`:** every benchmark, quality, portability, security, determinism, and artifact claim has an id, exact wording scope, state (`targeted|observed|evidenced|withdrawn`), validity domain, evidence artifact digests, expiry/revalidation trigger, and public surfaces allowed to repeat it. CI extracts claim ids from README/help/release templates and rejects wording stronger than the registry state. It does not pretend natural-language equivalence is decidable: public numeric/superlative claims must carry an explicit claim id.
- **`docs/BEHAVIOR_NOTES.md`:** intentional reference divergences and discovered upstream defects, each with source pin, minimized fixture, decision, compatibility impact, and expiry/revisit condition. Its seed entry is `BN-GEN-DEFAULT-001`: upstream `generation_config.json` defaults to sampling (`temperature=.6, top_k=20, top_p=.95`), while the reproducibility-oriented fnlp product defaults to greedy and requires explicit `--sample --preset nanbeige`; help, receipts, and fixtures expose that choice. This is separate from numeric `DISCREPANCIES.md` and never silently turns a reference bug into our specification.
- **`.fnlpr` evidence receipts:** canonical, schema-versioned JSON with a digest over the semantic request, artifacts, code/profile, datasets/fixtures, checks executed, output identities/digests, and evidence links. Private input/output bytes are absent by default and appear only under an explicit owner-authorized content-retention policy. Every receipt declares one completeness grade: `Replayable` (all authorized inputs/artifacts resolvable under that policy), `StructuralReplay` (structure/cost/provenance replayable but private content absent), `VerifiableIfArtifactsSupplied` (identities retained; caller must provide bytes), or `AuditOnly` (historical facts, no replay claim). A digest proves identity, not future resolvability; “verified receipt” without a grade is forbidden. Concurrency-failure evidence binds the lab seed, trace fingerprint, and crashpack id with its replay command, so a scheduler defect's receipt is `StructuralReplay`-grade by construction rather than a prose apology.
- **`docs/OPERATION_COSTS.json`:** exact structural witnesses emitted by scalar and optimized engines: invocation kind, loop passes, physical-layer executions, token positions, lm_head rows evaluated, candidate-trie nodes, KV logical/committed bytes, source-automaton transitions, cache hits by dependency scope, and generated tokens. A `target_full` invocation has exactly 2 loop passes and 44 physical-layer executions per token position. AA-D1's optional loop-1 draft projection is counted separately as `draft_loop1` with one pass plus its projection and can never be mislabeled as a target invocation. Equal semantic output cannot hide accidentally duplicated model work. Hardware time/energy remain benchmark measurements, not structural counters.

Each registry has a canonical schema, version migration policy (no compatibility shims before 1.0; regenerate deliberately), cross-reference validator, and frozen negative fixtures. These artifacts complement rather than replace L0–L5, task scorecards, hostile tests, or human review.

## 10. Performance methodology

Apply `/profiling-software-performance` then `/extreme-software-optimization`; `/alien-graveyard` + `/alien-artifact-coding` for the advanced families. Profile-first (no hotspot → no change), one lever at a time, keep-gate + revert discipline, `.bench-history` ratchet.

### 10.1 Regimes, rooflines, and honest ceilings

Profiles and ledgers are kept **per regime** because the cost center moves: **(R0) cold/warm startup** — process start → manifest/census ready → model ready → first token, measured separately under cold and warm filesystem cache and under owned versus mmap/auto loading, because for a 4+ GB artifact load/hash/page-fault behavior can dominate one-shot CLI usage even when steady-state decode is excellent (single-shot usability is never inferred from steady-state tok/s, and `fnlp batch` being the amortized path does not excuse pathological startup); **(R1) latency generate** (batch 1, decode-bound); **(R2) corpus scoring/classification** (prefill-dominated, prefix-cached, batch-M); **(R3) corpus generation** (summarize/extract batch, mixed); **(R4) long-context** (≥32K, attention/KV-bound). Per `(host fingerprint, artifact recipe, packing set, kernel table, load mode, regime)`, measure effective bandwidth and int8 throughput with the same access shapes, then compute memory/compute lower-bound models; report logical tensor bytes visited, packed payload bytes visited, measured DRAM bytes where counters support it, LLC/SLC misses or proxies, the effective bandwidth under each clearly labeled denominator, and whether loop 2 or subsequent tokens reused resident cache lines. STREAM peak, vendor TOPS, and the no-retention logical model are context, not attainable denominators, and none is labeled “actual bytes streamed.” A roofline gap becomes actionable only when counters/profile samples identify its cause and its EV score clears §10.4. Illustrative bandwidth-only ceilings below use a hypothetical 3.7 GB/token recipe and nominal memory bandwidth; they are not predictions:

| Machine | ~BW | decode ceiling |
|---|---|---|
| M4 Pro | ~273 GB/s | ~74 tok/s |
| M4 Max | ~410 GB/s | ~111 tok/s |
| TR 5995WX (Zen 3, 8ch DDR4) | ~205 GB/s | ~55 tok/s |
| TR 7995WX (Zen 4, 8ch DDR5) | ~333 GB/s | ~90 tok/s |

Batch-M shifts R2/R3 toward compute floors (the §6.7 amortization) — the measured docs/min table per machine is the headline artifact of Phase 4.

### 10.2 The optimization loop (mandatory)

The mandatory loop is: (1) freeze claim, code/artifact SHA, host fingerprint, workload, counters, warmup and baseline distribution; (2) change **one causal lever**; (3) prove the lever's equivalence/tolerance contract; (4) rerun randomized A/B trials through thermal steady state and report median, p95, p99, confidence interval, energy where available, and build/size cost; (5) keep only when the confidence interval and practical threshold both win, otherwise restore the baseline implementation while retaining the patch/commands/results in `NEGATIVE_EVIDENCE`. Coefficient of variation is diagnostic, not a universal 5% law. The benchmark harness is repository-owned over `std`/approved suite surfaces; a convenient framework name is not permission to add a fourth commodity dependency.

### 10.3 Head-to-head gauntlet vs the real baselines

`benches/gauntlet` drives a tested post-support official `llama.cpp` revision in an explicitly CPU-only configuration — recording its exact build flags, commit, GGUF recipe, mmap/page-cache mode, thread/affinity settings, prompt/template bytes, batch size, context, and output tokens, with GPU offload disabled for CPU claims — and CPU HF-if-proven with thread/allocator/precision/prompt/output parity; the authors' historical fork remains a supplementary lineage row. Trials are randomized paired A/B after warmup and thermal stabilization; report distributions and confidence intervals, never best-of-N. Comparison tables carry separate columns for raw model-kernel throughput; prompt/tokenizer/template overhead; FrankenNLP structural savings (prefix reuse, legal-row projection, batching) attributed separately; artifact bytes and total RSS; and locked task-quality deltas. Rows name **nearest format peers** (our int8 vs the Q8_0 class) plus matched-footprint and matched-quality views — never “matched quantization,” because the formats are not numerically identical. Slower rows remain. R4 context points are selected from admitted memory on the host, not hard-coded to 32K when it cannot fit.

### 10.4 Profile-gated lever queue and EV rule

Greenfield rankings are hypotheses, not profiles. The initial queue is: layer-major/morsel scheduling and prefix reuse (R2/R3); int8→int4 traffic reduction (R1); fixed-shape prepacked GEMM/GEMV (R1/R2); candidate-row lm_head (closed-set tasks); GQA attention/KV paging (R4); then M=1 non-temporal weight-stream experiments, exact radix/logit ordering for sampled generation, `resolve` pair-blocking, fusion/transcendentals, compact sparse grammar masks, NUMA/thread placement, and build recipes. Exact rule-union automata, CTZ bitset walks, static trie/catalog layouts, and UTF-8/NDJSON structural scanning enter only when their own profiles name them. Epoch reclamation is not an assumed upgrade: ordinary ownership/locks stay until measured contention and a memory-safety review justify even a research card. A card may enter implementation only when a measured hotspot maps to it and

`EV = (Impact × Confidence × Reuse) / (Effort × AdoptionFriction) ≥ 2`.

Scores are integers 1…5 with one-sentence evidence for each factor. Reuse matters: a kernel/scheduler lever that benefits four regimes outranks an exotic controller for one preset. One card, one causal change, one evidence ledger entry. If the hotspot disappears, the card returns to the queue.
