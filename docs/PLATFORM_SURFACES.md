# Platform Surface Registry

This registry is a release gate, not permission to add a platform binding.  A
facility is usable only after its row is changed to `available`, a named
`std` or pinned FrankenSuite surface is reviewed, and target-native evidence is
recorded.  Until then, `blocked` means the operation refuses and `off` means
the optional optimization is compiled out.  No release code may replace a
blocked row with a handwritten FFI declaration.

The terminal-component `O_NOFOLLOW` experiment in `60ac1f5` is partial opener
evidence only.  It does not prove effective-owner/ACL authority, does not bind
later child operations to a directory handle, and cannot provide a no-replace
final publish; all model-root rows therefore remain blocked and the CLI
continues to refuse mutation.

Ordinary swarm panes run no Cargo, RCH, DSR, or GitHub Actions command. The
controller may select one clean immutable SHA only after code-first contention
quiesces; an occasional DSR job then runs `scripts/check.sh` against the named
`production` graph. Direct RCH and GitHub Actions output cannot promote a row.
Even a green DSR code receipt does not make a platform row `available` without
the target-native evidence named here, and it cannot substitute for
model-present, performance, artifact, or human-review authority.

The intended distribution matrix is recorded with exact Rust target triples so
that the Phase-0 DSR receipt plus separate target-native evidence can ratify the
deployment baseline without changing the row identity:

- Linux x86-64 GNU: `x86_64-unknown-linux-gnu`; minimum glibc is not yet
  declared, and the GNU target ABI is the only current identity.
- Linux AArch64 GNU: `aarch64-unknown-linux-gnu`; minimum glibc is not yet
  declared, and the GNU target ABI is the only current identity.
- macOS Apple Silicon: `aarch64-apple-darwin`; minimum macOS deployment target
  is not yet declared.
- macOS Intel: `x86_64-apple-darwin`; minimum macOS deployment target is not
  yet declared, and this target remains conditional on the distribution matrix.
- Windows x86-64 MSVC: `x86_64-pc-windows-msvc`; minimum supported Windows
  release is not yet declared, and the MSVC x86-64 ABI is the current identity.

Every registry row has all of these required columns.  `Manual symbols` must
remain `NONE`; the authority column describes the OS contract that a future
reviewed safe surface would have to preserve, not an ABI that FrankenNLP may
call directly.

## Promotion and audit rules

1. A blocked or off row may move to `available` only with a pinned
   FrankenSuite or `std` surface, an explicit minimum platform baseline, and
   target-native tests for the listed invariants.  Capability detection alone
   is not an approval.
2. The Phase-0 G0 model-root crash-semantics ADR must name the relevant
   model-root `fs_tx` rows before atomic activation can ship.  Later mmap,
   `fs_tx`, tuning, durable jobs, and AA-R1 beads must update their affected
   row before shipping a facility.
3. `scripts/validate_platform_surfaces.py`, once the uxw scaffold supplies
   the DSR-run doc-validation leg, must parse this table, require every column
   above, print the complete facility-by-target matrix, and end with
   `PLATFORM_SURFACES RESULT=PASS|FAIL rows=<n> incomplete=<list>`.
4. G0 ADRs that consume a facility identify its exact `Facility` value on a
   standalone line as `PLATFORM_SURFACE: <facility>`.  The validator activates
   this cross-reference check as soon as `ADR-G0-*.md` files land, and reports
   any unknown facility as a documentation-gate failure.
